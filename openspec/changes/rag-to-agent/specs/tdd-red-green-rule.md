# TDD 红绿标记规则

> 编码: UTF-8 | 变更: rag-to-agent | 全局规则

---

## 规则概述

本项目遵循 **SDD → TDD** 流程。SDD 定义"做什么"，TDD 验证"做到了没"。红绿标记系统提供可视化的开发进度追踪。

---

## 规则内容

### 规则 1: SDD 与 TDD 同步生成

- 每完成一个模块的 SDD spec，立即生成对应的 TDD 测试文件
- TDD 测试文件中的所有测试用例初始标记为 `RED`
- 测试用例编号与 `specs/test-cases.md` 中的用例 ID 一一对应

### 规则 2: 全线标红启动

- 新增模块（模块代码未开始编写）时，对应 TDD 文件中 `TEST_STATUS` 全部为 `"RED"`
- 运行测试预期输出: 全部 `[RED]`，汇总状态: "全部 RED - 模块尚未实现，等待开发"

### 规则 3: 通过后变绿

- 开发实现模块代码后，运行对应 TDD 测试
- 测试通过的用例，将 `TEST_STATUS` 中对应条目从 `"RED"` 改为 `"GREEN"`
- 修改后提交到版本控制，作为开发进度的记录

### 规则 4: 每阶段回归

- 每个开发阶段完成后，运行所有 TDD 测试确认进度
- 同时运行回归测试（`tests/tdd_all_optimizations.py`）确保管道模式不受影响
- 全 GREEN 后，本阶段完成

### 规则 5: 测试实例积累

- 开发过程中发现的新边界条件、异常场景，应补充到对应 TDD 文件中
- 补充的测试也遵循红绿规则（新增时标 RED，通过后变 GREEN）

---

## 标记状态说明

| TEST_STATUS 值 | 含义 | 运行输出 |
|:---:|---|:---:|
| `"RED"` | 模块尚未实现，测试预期失败 | `[RED]` |
| `"GREEN"` | 模块已实现，测试预期通过 | `[GREEN]` |

### 特殊情况

| 情况 | 检测方式 | 输出 | 处理 |
|------|---------|:---:|------|
| 标记 RED 但测试通过 | 测试条件为 True | `[WARN]` | 提醒开发者更新标记为 GREEN |
| 标记 GREEN 但测试失败 | 测试条件为 False | `[FAIL]` | 说明代码回归，需修复 |

---

## 文件结构约定

每个 TDD 测试文件包含:

```python
# 1. 文件头（UTF-8 编码声明 + 文件说明）
# 2. TEST_STATUS 字典（红绿标记登记表）
# 3. 全局计数器 (passed/failed/red_count/green_count)
# 4. check() 函数（统一断言函数，自动读取 TEST_STATUS）
# 5. 模块导入尝试（try/except ImportError）
# 6. 测试用例（按 test_id 编号排列）
# 7. 汇总输出（统计 RED/GREEN 分布）
```

---

## 执行顺序

```
SDD spec 完成
  → 生成 TDD 测试文件（全部标 RED）
    → 开发模块代码
      → 运行 TDD 测试
        → 测试通过 → 改标记为 GREEN → 提交
        → 测试失败 → 修复代码 → 重新运行
      → 全部 GREEN
    → 运行回归测试（tdd_all_optimizations.py）
  → 本阶段完成 → 进入下一阶段
```
