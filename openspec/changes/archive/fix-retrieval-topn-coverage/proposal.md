# 变更提案: 修复多公司检索 top_n 过小导致公司被顶掉

> 编码: UTF-8

## 背景

查询「三大运营商2024年营收都是多少」时，检索结果缺失「中国移动」。

根因：Agent 调用 retrieve 工具时传 `top_n=3`，而检索系统对「三大运营商」检索了全部 4 家公司（移动/电信/联通 + 中芯国际）。重排后 top 3 落在电信/联通上，触发公司覆盖保底逻辑；因 3 个名额装不下 4 家公司，保底逻辑在「移除最低分」分支里把中国移动（rerank=1.5）顶掉，换入中芯国际（rerank=1.5），最终结果缺失中国移动。

## 目标

多公司检索时，将 `top_n` 自动扩容到至少等于待检索公司数，确保每家公司至少保留 1 条结果，避免保底逻辑互相顶替。

## 方案

在 `HybridRetriever.search()` 确定 `companies` 后，新增纯函数 `_adjust_top_n_for_companies(top_n, companies)`：

- 当 `len(companies) > 1` 且 `top_n < len(companies)` 时，返回 `len(companies)`；
- 否则返回原 `top_n`。

## 非目标

- 不改变单公司检索、对比查询（comparison intent）的既有逻辑。
- 不实现「运营商集合」等公司识别能力（中芯国际仍会被检索，但不挤占名额）。
- 不涉及前端。
