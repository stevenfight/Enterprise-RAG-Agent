# 变更提案: 模型升级与检索精准度提升

> 编码: UTF-8
> 状态: 已完成

---

## 1. 变更背景

当前系统在以下场景中存在准确度不足的问题:

- **表格数据检索弱**: 营收、利润等关键财务数据以表格形式呈现,向量 Embedding 对表格文本语义理解不足,导致检索命中率低(BUG-015/019)
- **重排效率低且评分不一致**: LLM 逐条重排导致 30-60 秒延迟,且独立调用导致评分标准不统一
- **生成答案幻觉风险**: qwen-plus 在财报精确数据引用场景下指令遵循能力不足

## 2. 变更目标

| 目标 | 衡量标准 |
|------|----------|
| 提升检索命中率 | 三家运营商营收对比查询,每家公司营收数据均出现在 top 5 结果中 |
| 提升重排准确度与速度 | 重排耗时从 30-60 秒降至 5 秒以内,评分一致性提升 |
| 提升生成答案质量 | 数据引用准确率提升,幻觉率降低 |

## 3. 变更范围

### 3.1 Embedding 模型升级 (P0)

| 项目 | 当前 | 变更后 |
|------|------|--------|
| 模型 | `text-embedding-v1` | `text-embedding-v3` |
| 维度 | 1536 | 1024 |
| 涉及文件 | `src/retrieval.py` (第45-46行), `src/ingestion.py` (第37-38行) | 同 |

**前置条件**: 变更后必须重建所有 FAISS 索引

### 3.2 重排模型替换 (P1)

| 项目 | 当前 | 变更后 |
|------|------|--------|
| 模型 | `qwen-plus` (通用 LLM 逐条调用) | `gte-rerank` (专用重排模型批量调用) |
| 调用方式 | `dashscope.Generation.call()` | `dashscope.TextReRank.call()` |
| 涉及文件 | `src/retrieval.py` (`_llm_rerank` 方法,第479-554行) | 同 |

### 3.3 生成模型升级 (P2)

| 项目 | 当前 | 变更后 |
|------|------|--------|
| 答案生成模型 | `qwen-plus` | `qwen-max` |
| 意图识别模型 | `qwen-plus` | 保持不变 |
| 涉及文件 | `src/retrieval.py` (第896行 `GENERATION_MODEL`) | 同 |

## 4. 不变更的范围

- PDF 解析模型 (MinerU vlm): 已是最优,不变更
- 意图识别/查询改写模型 (qwen-plus): 轻量任务,plus 足够
- 分块策略 (Small-to-Big): 本次不变更,后续迭代考虑
- Streamlit 前端界面: 无需变更

## 5. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| text-embedding-v3 API 接口变化 | 调用方式可能不同 | 先验证 API 兼容性 |
| FAISS 索引重建耗时 | 需要重新调用 Embedding API | 保留旧索引备份 |
| gte-rerank API 可能不支持某些参数 | 重排逻辑需适配 | 先测试 API 行为 |
| qwen-max 费用高于 qwen-plus | 生成成本增加 | 仅用于最终答案生成 |

## 6. 依赖项

- DashScope API Key (已有)
- `text-embedding-v3` 模型在 DashScope 平台可用
- `gte-rerank` 模型在 DashScope 平台可用
- `qwen-max` 模型在 DashScope 平台可用
