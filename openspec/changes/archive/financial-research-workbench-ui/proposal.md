# 变更提案：财务研究工作台 UI 改造

## 背景

当前前端已具备智能问答、Agent 执行过程、图表、DAG、知识库和系统状态等能力，但这些能力分散在五个偏工具化页面中。整体视觉仍采用马卡龙粉紫和玻璃拟态，和企业财务研究所需要的可信度、数据密度及长文阅读体验不完全匹配。

本变更将前端从“功能集合”调整为“财务研究工作台”：以一个研究任务为中心组织问题、结论、关键指标和可核验证据，同时保留现有路由、API 和 Agent 能力。

## 目标

1. 建立适合财务研究的设计系统：浅色研究画布为默认，深色专注分析模式为可选主题，并支持金融青绿与深蓝两套主体色即时切换。
2. 将聊天首页改造成研究工作台，串联公司范围、提问、结论、KPI、引用和可核验分析过程。
3. 升级图表、知识库、DAG、设置页面的信息层级和状态表达，统一为同一套研究语言。
4. 保持现有 API 契约和业务能力，首期不依赖新增后端字段。

## 非目标

- 不改变 RAG、Agent、检索、鉴权、SSE 或数据入库业务逻辑。
- 不展示或新增模型内部思维链；仅展示用户可核验的工具、检索和证据过程。
- 不通过文件名推断并显示公司、报告年度、章节或可信度等未知元数据。
- 不将回答级来源伪装为某个 KPI 的逐项引用，也不擅自换算、汇总或赋予财务数值涨跌语义。
- 不展示原始工具输入、请求头、令牌、密钥、运行配置或堆栈等可能包含敏感信息的过程字段。
- 不将上述原始过程字段写入浏览器会话持久化；对既有浏览器会话中的过程字段只做安全投影或清理，不影响用户问题与最终回答。
- 首期不新增“保存研究报告”“团队协作”“文档全文预览”等需要后端持久化的数据功能。
- 不重构为 Ant Design Pro、Tailwind 或其他前端框架。
- 不提供任意自定义取色；首期仅提供经对比度验证的金融青绿和深蓝两套主体色，语义色与多序列数据色不随主体色切换而失真。

## 交付边界

本变更分为四个工作包：

1. 设计系统与全局工作台框架。
2. 智能问答页的研究工作台重构。
3. 图表、知识库、DAG、设置页的一致性升级。
4. 响应式、可访问性、性能与视觉验收。

## 成功标准

- 用户在首页可在一个上下文中看见研究范围、提问、结论、KPI、引用与任务状态。
- 默认界面具备企业研究产品的清晰层级，不再以马卡龙渐变和大面积玻璃效果作为主视觉。
- 所有既有路由和核心交互可用；前端现有测试、构建与新增 TDD 验收通过。

## 后续视觉方向决策（v1.22）

经三种概念稿对比，后续不再以“逐页增加卡片装饰”为主要方向，而采用“证据驱动研究 Copilot”作为整体母版：默认浅色研究画布服务长文阅读和证据核验，深色分析驾驶舱作为可选专注模式。该决策不改变本变更的 API、隐私和数据边界；它只重新组织现有前端能力的呈现顺序。

## C8：Agent 回答证据与研究结果密度

Agent 模式目前只在最终 SSE 事件中返回回答正文，尽管单 Agent 和多 Agent 已收集检索来源，前端消息并未获得回答级来源，因而只能如实显示“暂无引用来源”。本工作包补齐来源契约，并在不伪造证据、置信度或进度的前提下，依次提升回答页的研究摘要、来源导航和桌面端信息密度。

### 成功标准

- Agent 最终回答仅携带其实际检索到的、结构化且去重的回答级来源；没有来源时保持真实空状态。
- SSE 与非流式 Agent 响应的来源结构和 RAG `SourceInfo` 一致，前端能随当前回答保存和展示。
- 回答区只展示服务端实际返回的范围、模式、耗时和来源数量，不引入推测性“可信度”或模拟分析进度。

## C9：证据驱动研究报告画布

当前工作台已具备回答级证据与安全过程，但主区仍以通用消息气泡为主，右栏也按单条来源平铺。因此它可用，却没有形成财务研究产品的阅读体验与项目辨识度。本工作包将桌面端当前回答重组为“研究问题—结论正文—已核验比较/既有 KPI—证据包—执行摘要”的研究报告画布。

### 范围与边界

- 只重组已存在且可追溯的数据：问题文本、回答正文、回答创建时的 `researchMeta`、`SourceInfo`、已有 KPI 识别结果、已核验比较事实和安全 `AnalysisTraceStep`。
- 证据包按公司、报告文件聚合重复来源，合并现有页码并保留所有来源编号；不从文件名推断年份、章节或引用次数。
- 没有数值 `hybrid` 分数的 Agent 来源不显示“检索匹配度未提供”，而显示中性的“回答证据”；RAG 来源保留已有检索匹配度语义。
- 不把回答级来源声称为某个 KPI 的精确出处，不自动从回答 Markdown 生成趋势图、投资评级、风险结论或置信度。
- 首期不新增报告保存、导出、协作、PDF 全文预览、后端指标抽取或新的 LLM 调用；这些能力需独立数据契约。

### 成功标准

- 桌面端助手回答从通用对话气泡升级为可阅读的研究报告卡片，用户问题保持轻量提问形态。
- 回答有真实研究上下文、结论正文、仅在数据存在时显示的比较/KPI 区，以及明确的证据入口。
- 右侧证据包按公司/报告去重聚合，不显示无意义的“匹配度未提供”，并保持来源真实可回看。
- 既有 RAG、Agent SSE、会话、来源选择、取消处理和安全过程展示不回归。

## C10：按需证据工作栏与视觉收口

当前桌面端证据栏永久占用右侧宽度，导致研究报告主区被压缩为又一个普通三栏后台。C10 将证据栏改为由当前回答的“查看证据”入口或工作台快捷入口按需打开的右侧工作栏；关闭后主阅读区恢复全宽。

### 范围与边界

- ≥1200px 时默认不渲染常驻证据栏；打开后只显示当前选中回答的证据和安全分析过程，关闭后不改变消息、会话或请求状态。
- <1200px 继续使用既有互斥 Drawer，不新增第二套窄屏交互。
- 统一用户问题与报告卡的主体色，移除本轮触及区域的紫色主视觉；只使用既有主题语义变量，不新增视觉示意数据。
- 不新增后端字段、报告能力、图表、评级、风险结论或前端依赖。

### 成功标准

- 默认桌面主区获得完整阅读宽度；点击“查看证据”后才打开右侧工作栏，关闭按钮可恢复主区。
- 顶部入口与历史回答入口均定位至对应回答来源；空来源仍显示真实空状态。
- 打开/关闭证据栏不影响 RAG、Agent SSE、输入草稿、会话选择或安全过程边界。

## C11：已核验比较正文一致性

### 背景

当前三大运营商 2024 年营业收入问题中，已核验比较卡片使用事实注册表显示中国移动 10,408 亿元，但 RAG 正文仍由模型根据检索片段独立换算，可能将“1,040,759 百万元”误写为“104.08 亿元”。同一回答中存在互相矛盾的数值，不能以卡片覆盖正文错误。

### 范围

- 对事实注册表已支持的完整比较问题，正文直接使用同一份已核验事实生成，并列明公司、统一单位、年报文件和页码。
- 保留原有检索和回答级来源摘要，以便证据工作栏继续展示真实检索来源。
- 未登记问题保持现有 RAG 生成路径；不扩展事实注册表覆盖范围，也不改动前端数值展示。

### 成功标准

- “对比三大运营商2024年的营业收入”的正文与已核验卡片均显示中国移动 10,408 亿元，不出现 104.08 亿元。
- 已登记问题不调用模型生成其比较正文；未登记问题仍可调用原有模型生成路径。

## C12：正文引用与证据工作栏联动

### 范围

- 回答 Markdown 中已有的 `[来源N]` 仅在该回答存在同编号 `sources` 时渲染为可访问的定位按钮。
- 点击后打开当前回答的证据工作栏，自动展开所属“公司 + 报告”证据组，并高亮对应单条来源。
- 桌面与窄屏继续复用现有工作栏与 Drawer；不新增 PDF 预览、文档跳转、后端接口或来源推断。

### 成功标准

- 未匹配的 `[来源N]` 保持普通文本，不能打开其他回答或伪造证据。
- 切换会话、关闭工作栏或选择另一条回答后，高亮状态不会残留。

## C13：已核验多公司对比可视化

当前已核验比较卡片能准确展示数值和出处，但仍是纯数字列表，难以快速传达公司间的量级关系。本工作包只消费回答随附的 `comparison` 结构化事实，为两家及以上公司增加简洁的研究摘要与横向对比视觉。

### 范围与边界

- 仅在 `comparison.available` 且至少含两项事实时展示；单公司或无结构化事实时保持现有克制展示。
- 领先公司、最大值、与第二名的差额和横向条形比例均由现有 `company_name`、`value`、`unit` 派生，不读取或推断回答正文。
- 每家公司仍展示精确值、单位、报告文件和页码；横向条形仅帮助阅读，不能替代数值或来源。
- 不新增后端字段、图表库、模型调用、财务换算、同比推断或投资结论。

### 成功标准

- 三家运营商营业收入回答可在同一张已核验卡片中直观看到 10,408、5,236、3,896 亿元的相对规模，同时保留逐项出处。
- 图形具备可访问名称和等价文字，且不会把单公司事实伪装成比较结论。

## C14：研究交付摘要层

研究报告卡片已有研究上下文，但当前以一行元文本呈现，不能形成首屏的研究交付感。本工作包将回答随附的真实模式、范围、来源数量、耗时和已核验比较状态重组为紧凑摘要层，让用户先读到“本次交付是什么、基于什么”，再进入正文。

### 范围与边界

- 只使用回答持久化的 `researchMeta`、`sources` 和 `comparison.available`；不得根据正文推测数据质量、可信度、公司、指标或结论。
- 有已核验比较时可如实显示“已核验比较”；其他回答只显示中性的“已生成回答”。
- 摘要层为只读信息层，不新增报告保存、评级、风险、导出、协作或后端字段。

### 成功标准

- 带研究元数据的回答首屏展示可访问的交付摘要，包含真实研究方式、范围、证据数量、处理耗时与真实结论状态。
- 历史回答或无研究元数据回答保持原有普通阅读结构。

## C15：已核验对比到证据的一跳核验

正文 `[来源N]` 已能定位证据，但用户阅读多公司对比卡时仍需先找来源编号再跳转。C15 让已核验比较中的公司行在存在同一回答的精确来源时直接打开并高亮该来源，缩短核验路径。

### 范围与边界

- 仅当当前回答的 `sources` 中存在公司、报告文件和至少一个页码均匹配的来源时，才提供公司行的证据入口。
- 点击复用 C12 的当前回答工作栏、展开与高亮机制；不新增 PDF 预览、文档跳转或后端接口。
- 找不到当前回答对应来源时，比较事实继续静态显示，不把注册表出处猜测为回答级来源。

### 成功标准

- 三大运营商比较卡中的公司行可直接定位本回答对应的证据卡。
- 不属于当前回答或页码不匹配的来源不能成为可点击入口。

## C16：已核验图表成果一致性

图表中心直接读取历史图表产物，可能保留早期模型生成的错误数值，即使同一问题的回答正文与比较卡片已由事实注册表校正。本工作包只对已登记的“2024 年三大运营商营业收入”完整比较，在图表列表返回前从同一事实注册表投影数值与页码；其他图表、其他指标和未登记问题保持原样。

### 成功标准

- 图表中心中命中该完整比较的柱状图与表格均显示中国移动 10,408、中国联通 3,896、中国电信 5,236 亿元。
- 不以标题、文件名或公司名称猜测未登记的财务事实；未命中注册表的图表产物不被改写。

## C17：研究启动与配置职责收口

首页启动区已提供示例问题，但研究配置抽屉再次复制相同内容，导致“直接开始研究”和“调整范围/模式”混杂。本工作包保留启动区作为唯一示例问题入口，并将配置抽屉限定为影响下次提问的公司范围、RAG/Agent 模式及高级参数。

### 成功标准

- 打开研究配置不会再看到示例问题；首页空会话仍保留示例问题并可直接发送。
- 公司范围与 Agent 模式的现有 Store、持久化和请求参数路径不改变。

## C18：研究范围摘要即配置入口

顶部摘要同时承担当前研究条件的可见性与调整入口；若另外保留“研究配置”按钮，会再次出现两个入口。将“下次提问：公司范围”的摘要收敛为唯一可访问按钮，点击即可打开既有配置抽屉；分析模式标签仍保留为只读状态提示。

### 成功标准

- 有配置回调时，顶部研究范围摘要是带明确无障碍名称的唯一配置入口，并能打开原有配置抽屉。
- 不再渲染独立“研究配置”按钮；证据入口、模式展示和既有配置内容不改变。

## C19：顶端内联研究配置

研究范围摘要已是唯一配置入口，但点击后仍打开抽屉，操作上下文被遮挡。将该入口改为在研究工作台顶端展开或收起内联配置带，直接选择公司、RAG/Agent 模式与既有高级参数。

### 成功标准

- 点击范围摘要后，在工作台顶端显示“研究配置”内联区域，而不是弹窗或 Drawer。
- 内联区域复用现有公司选择、检索条数、Agent 开关和步数上限的状态、持久化及请求参数。
- 示例问题仍只在启动页显示；证据工作栏、会话抽屉和分析过程不改变。

## C20：工作台右侧直配研究条件

研究范围摘要展开内联配置后，顶端仍要经历一次“打开配置”的操作，且配置带会压低报告首屏。将影响下次提问的核心条件收敛到研究工作台顶栏右侧：公司范围与 Agent 模式可直接调整，高级参数按需在同一上下文中展开。

### 范围与边界

- 顶栏右侧常驻公司选择和 Agent 开关；关闭 Agent 即保持既有 RAG 请求路径。
- 检索返回条数和 Agent 步数上限只在“高级选项”展开区显示，复用现有状态、持久化和请求参数。
- 小于桌面宽度时配置控件可换行显示，不能改回 Dialog、Drawer 或遮挡式弹窗。
- 不改动回答、证据工作栏、图表、后端接口、会话与请求实现，也不增加新的配置字段。

### 成功标准

- 初始进入工作台即可在顶栏右侧找到“研究配置”区域中的公司选择、Agent 开关与高级选项，不需要点击范围摘要。
- 展开高级选项只显示已有高级参数；不展示示例问题，不出现同名 Dialog 或 Drawer。
- 切换公司或模式继续使用既有 Store 与请求参数路径，证据入口保持可用。

## C21：研究回答阅读与引用节奏

研究报告画布已具备真实元数据、核验比较和回答级来源，但长正文、Markdown 表格与独立来源编号在同一阅读面内会产生拥挤或横向溢出。本工作包只优化阅读容器与引用排版，不改变模型回答、已核验事实、来源编号、证据定位和后端契约。

### 范围与边界

- 研究报告正文使用受控阅读宽度、稳定段落间距、标题和列表节奏；不删改回答文本。
- Markdown 表格置于可横向查看的语义容器，保留全部列、单元格和来源编号，不能以裁切或省略代替。
- 单独成段的现有 `[来源N]` 引用收为紧凑引用行；编号继续调用既有当前回答证据定位。
- 不改动用户问题气泡、证据工作栏内容、财务数值、文档页码、请求或 Store。

### 成功标准

- 带研究元数据的回答在报告正文内具有可识别的阅读面；长表格不会撑破消息宽度。
- 正文与表格外的当前回答来源编号仍可点击定位，且视觉上不再像脱离内容的普通段落。
- 无研究元数据的历史回答保持既有普通阅读结构。

## C22：研究启动动线与输入入口

空会话首屏同时存在大标题、范围胶囊、问题卡和三项能力说明，用户视线在多个同权元素间跳转；底部输入框虽可用，却没有成为主操作。将启动页收敛为“研究定位—示例问题—输入提问”的单一动线，能力说明降为紧凑可信信号，并强化既有输入框的研究入口质感。

### 范围与边界

- 保留真实研究范围、模式、示例问题、三项已有能力及其点击发送行为；只改变启动页的视觉层级与结构。
- 输入框不新增请求类型、附件、联网或模型能力；保留 Enter/Shift+Enter 与加载禁用语义。
- 空会话启动页不得因消息自动滚动逻辑而被滚离顶部；已有回答与加载过程继续自动定位到最新内容。
- 不改动顶栏右侧研究配置、会话列表、回答、证据工作栏或后端接口。

### 成功标准

- 空会话首屏以示例问题和输入提问为连续主路径，三项能力不再以等权卡片分散注意力。
- 输入框具有专属研究入口样式钩子，并保留既有 Sender、占位提示、发送和禁用行为。
- 启动页继续如实展示当前公司范围、模式及回答/证据/分析过程能力。

## C23：研究元信息去重与动作克制

模式、范围、来源数量和耗时在全局顶栏、工作台摘要、启动页和回答交付摘要多处重复，稀释了研究结论本身。本工作包将回答交付摘要压缩为一条可扫读的真实交付信息，并移除研究摘要条中已被直接配置控件表达的重复模式标签。

### 范围与边界

- 回答中仍完整展示其自身保存的模式、范围、证据数、耗时与交付状态，只改变为紧凑信息行。
- 顶栏右侧公司和 Agent 控件仍为唯一可编辑设置；全局顶栏的运行期模式摘要保持不变。
- 不删改回答、来源、事实、会话历史数据或可访问的证据入口。

### 成功标准

- 研究报告的交付信息不再使用四个等权数据格，但历史回答真实元数据仍可被阅读与测试。
- 工作台摘要条不再重复显示只读 RAG/Agent 标签；公司选择、Agent 开关和证据入口保持可用。

## C24：研究画布微交互收口

最后一层视觉完成度来自低频但持续可见的细节：原生滚动条、回答底部操作和键盘焦点不能割裂研究画布。本工作包为既有内容滚动区和助手回答操作补充统一样式钩子与克制反馈，不新增任何动作或改变加载流程。

### 范围与边界

- 只为既有消息滚动区和“复制/重新生成”操作增加语义样式钩子与 CSS 反馈。
- 保留已有 hover 显示、复制、重新生成、键盘焦点和滚动行为。
- 不新增模拟进度、骨架屏、通知、请求、数据字段或前端依赖。

### 成功标准

- 主消息滚动区和回答操作有明确的可复用样式钩子，细节可统一为研究画布语言。
- 既有操作只有在原条件下出现，复制/重新生成与来源入口行为不回归。
## C25：视觉层级收口（2026-08-26）

在不改变问答、检索、公司范围、Agent 或证据数据契约的前提下，收敛研究工作台的首屏与回答态：欢迎页不重复显示已由顶端直配区承担的范围和模式；输入区明确发送语义；研究报告将交付信息作为紧凑前言；已核验比较与 Markdown 表格统一使用既有财务主题变量。验收以 C25 的 RED→GREEN 组件测试、全量前端回归和真实浏览器查询为准。

## C26：研究终端跨页信息架构（2026-08-26）

将辅助页从同质化后台卡片重组为研究终端的四类工作区：图表为成果浏览，资料库为证据资产，DAG 为待生成或已生成的执行轨迹，系统状态为研究运行保障。仅复用当前接口返回的成果、文件、计划和状态数据；禁止由文件名推断资料属性，禁止在空态虚构 Agent 执行数据。

## C27：回答到成果的可核验闭环（2026-08-26）

已核验比较可将用户带入图表成果页，并传递比较本身已携带的指标、年度和单位作为浏览条件。图表 API 目前没有回答 ID 或图表 ID 的关联字段，因此页面只能标明“按研究条件浏览”，并仅依据真实图表标题做透明的候选匹配；不允许宣称某张历史图表由当前回答生成。

## C28：Agent 图表公开地址契约（2026-08-26）

图表工具生成 PNG 后，只向 Agent 输出浏览器可访问的 `/api/charts/images/` 地址及由工具生成的标准图片 Markdown。不得把服务器本地文件路径或相对文件路径交给 Agent 作为回答素材；图表中心继续使用既有 JSON 和数据字段。
