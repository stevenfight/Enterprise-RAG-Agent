# 设计：财务研究工作台 UI 改造

## 1. 产品定位与设计原则

产品定位为“企业年报研究助手”，而不是通用聊天机器人或交易终端。设计语言采用：

- 默认浅色研究画布：服务年报阅读、长回答和证据核验。
- 可选深色专注分析模式：服务图表、DAG 和高密度分析，不作为强制默认。
- 单一主体色：金融青绿或深蓝，由用户即时切换；涨跌、警告、错误只使用语义色。
- 结论优先、证据紧随、过程按需展开；避免同权重的卡片堆叠。
- 数字使用现有等宽字体栈，正文保持清晰中文无衬线字体。

不采用当前“马卡龙 + 大面积渐变 + 玻璃拟态”作为主视觉。圆角、阴影和渐变只用于层级区分，不能替代信息组织。

## 2. 信息架构

全局一级导航保留五个能力入口，但改用研究语言：

| 现有路由 | 新名称 | 主要职责 |
|---|---|---|
| `/` | 研究工作台 | 发起问题、阅读结论、核验证据、查看任务进度 |
| `/charts` | 分析成果 | 浏览已有图表与数据表，不承诺保存研究报告 |
| `/knowledge` | 资料库 | 管理可用年报和索引状态 |
| `/dag` | 分析流程 | 高级用户查看任务规划与执行批次 |
| `/settings` | 系统状态 | 查看模型、向量库、记忆和工具状态 |

所有页面在顶栏或页首显示统一的研究上下文。`HeaderBar` 在 ≥1200px 时以内联只读摘要展示“下次提问范围”和模式，在 768–1199px 时收纳为带可访问名称的只读上下文按钮，在 <768px 时以底部抽屉展示同一摘要；三种形态都不得提供第二个编辑入口，也不得与主题、健康状态和固定输入区重叠。顶栏继续复用 `AppLayout` 的 `checkHealth()` 结果显示“检查中/已就绪/暂不可用”；首页的 `ResearchContextBar` 是唯一可编辑入口。首期在现有 Zustand 前端 Store 中使用应用级运行期 `researchContext` 供各路由读取：`companyName` 是唯一的运行期公司范围来源，不进入任何浏览器持久化；`mode` 是现有 `agent-mode` 浏览器偏好加载后的运行期投影，必须在 Store 创建时同步初始化，保证直接进入任意路由的顶栏也如实显示偏好。用户切换模式时必须同步更新偏好和投影，不能把两者视作独立可竞争来源。`ChatPage` 直接订阅 `researchContext.companyName` 并通过 `setResearchContext` 修改，不保留会在挂载时回写空值的本地公司状态镜像。刷新后公司范围重置，模式按既有偏好恢复；二者都不写入 `chat-sessions` 或后端，也不伪造跨设备研究项目。`topN` 和 `agentMaxSteps` 保持为首页高级选项，不进入跨路由上下文。

已有聊天会话会按现有机制保存在浏览器中，因此研究上下文只能表述为“下次提问条件”，不得为历史消息补写或推断公司范围、模式。历史问答必须保持其原有内容，不以当前 `researchContext` 标记其检索条件。

## 3. 首页：研究工作台

桌面端采用“主画布 + 可收起证据面板”的双栏，不新增第三个永久导航栏：

```text
全局导航 | 顶栏：研究范围 / 系统状态 / 主题
---------+------------------------------------------------
         | 研究摘要条：公司范围、模式、当前会话、数据提示
         |------------------------------------------------
         | 主研究画布                    | 证据与过程面板
         | - 欢迎与研究模板              | - 来源文件与页码
         | - 问答与流式结论              | - 检索融合分说明
         | - KPI 重点指标                | - 工具调用、观测摘要
         | - 图表/引用入口                | - 待核验提示
         |------------------------------------------------
         | 固定输入区：提问、公司范围、Agent 开关
```

### 3.1 组件映射

| 新组件/区域 | 复用或改造来源 | 数据边界 |
|---|---|---|
| `ResearchContextBar` | `ChatPage` 的公司选择、Agent 开关、会话状态 | `getCompanies`、本地会话状态 |
| `ResearchWelcome` | 示例问题和 `ChatContainer` 空状态 | 仅静态研究模板与已有公司列表 |
| `ResearchAnswerCanvas` | `MessageBubble`、`FinancialKPICards` | 现有问答响应和消息 Store |
| `EvidencePanel` | `SourceCard` | 回答级 `SourceInfo.source_file`、`pages`、`scores`；分数标注为“检索匹配度”，不声明 KPI 逐项引用 |
| `AnalysisTracePanel` | `ThoughtChainDrawer` | 仅展示工具名称、输入摘要、观测摘要、耗时和完成状态 |
| `ResearchComposer` | `ChatInput` | 保留 Enter/Shift+Enter 与流式禁用逻辑 |

### 3.2 分析过程约束

当前 `ReasoningStep` 包含 `thought`、`action`、`observation`。首期界面只向用户展示：

- 操作名称和简化后的输入条件；
- 可核验的检索/工具观察结果；
- 步骤序号、耗时、完成/警告状态；
- 强制停止或缺少证据时的风险提示。

不得把 `thought` 文本作为产品内容展示。现有 `MessageBubble` 内嵌步骤预览和 `ThoughtChainDrawer` 都必须重构：抽屉重命名为“分析过程”，两处均移除内部思维文本区域。

`action_input` 和 `observation` 也不能原样透传到界面。实现时应按工具类型采用允许展示字段清单、长度上限和敏感键名脱敏；密钥、令牌、授权信息、请求头、运行配置、文件绝对路径、堆栈及无法归类的原始输入均不得展示。没有可安全展示的内容时，只显示工具名称、步骤状态和“未提供可展示摘要”。

安全投影必须发生在 SSE 事件写入消息 Store 之前，而非仅在组件渲染时隐藏。新增前端 `AnalysisTraceStep` 安全过程视图模型，并让 `agentEvent` 以该模型累积过程数据；`Message.reasoningChain` 与 `ThoughtChainDrawer` 不再以包含 `thought` 的后端 `AgentStepInfo` 作为显示/持久化类型。模型仅允许 `toolLabel`、受控 `inputSummary`、受控 `observationSummary`、步骤号、耗时和状态：工具名、Worker 名称及输入键均须经前端白名单映射为产品标签，未知值统一显示“分析工具”或“协同任务”，绝不回显原始字符串。输入摘要只能由已注册工具的安全字段生成，未知工具或字段不生成摘要。

`chatStore` 持久化前只保存安全模型：单 Agent 不含 `thought`，多 Agent 丢弃 `step_type = thought` 的内容，仅保留映射后的 Worker 标签、状态、已完成步骤数和耗时。加载旧 `chat-sessions` 时需清理遗留的内部思维、原始输入、原始观测、原始工具名和 Worker 名称，并立即回写已清理的会话；用户消息与最终回答不受影响。

已有 `agentEvent`、`MessageBubble`、`ThoughtChainDrawer` 与 `HeaderBar` 测试中对原始过程内容或布尔健康状态的断言必须改为安全模型与三态状态断言；不得通过删除既有测试来规避回归。

### 3.3 财务数字与证据语义

- KPI 必须按现有解析结果原样显示 `value` 和 `unit`；首期不得在前端换算单位、合并口径、补全币种或推导同比。
- 收入、利润、ROE、毛利率等普通财务数值采用中性正文色，不因数值为正而显示为“利好”；只有解析器明确标记方向的增长类指标才可使用上涨/下跌语义色，并同时提供箭头和文字。
- 现有 `SourceInfo` 只能作为回答级证据。首期可在答案旁展示来源文件、页码和“检索匹配度”，但不得声称某一 KPI 已有逐项来源映射；该能力需要后端返回可靠的指标—来源关联后另行设计。

### 3.4 已核验比较的视觉表达（C13）

`VerifiedComparisonCard` 只在随回答附带的 `comparison.available` 为真、且有至少两家公司时，展示“最高值”和“领先第二名”的派生摘要，并在每个原有事实行中增加按最大值归一化的横向量级条。公司名称、精确数值、统一单位、来源文件和页码继续同屏可见。量级条标记为装饰性；列表项提供包含精确值和相对比例的可访问文本。

派生摘要只比较本次 `comparison.items` 内的 `value`。当只有一项、数值不为正或结构缺失时，不渲染摘要或条形可视化，避免把单一事实包装成对比结论。样式复用当前主题的主体色与边框变量，不引入图表依赖或额外数据语义。

### 3.5 研究交付摘要层（C14）

带持久化 `researchMeta` 的回答在正文前显示紧凑的“研究交付摘要”。摘要卡只显示回答真实生成时的研究方式、研究范围、回答级证据数量、服务端耗时，以及由 `comparison.available` 决定的“已核验比较”或“已生成回答”状态。它不表达证据质量、置信度、投资建议或任何未返回的财务属性。

摘要采用小型信息格而非新增常驻面板，桌面端可在首屏快速扫描，窄屏自动换行。每项均有文字标签，图标仅作辅助；现有正文、比较卡、来源定位和页脚操作顺序保持不变。

### 3.6 已核验比较一跳核验（C15）

`VerifiedComparisonCard` 接收当前回答的 `SourceInfo`，只以“公司名、报告文件、至少一个页码”三项同时匹配决定公司行是否可点击。匹配时使用可访问按钮触发已有的回答级来源定位回调；未匹配时保留普通静态行。比较注册表本身不是回答级来源，因此绝不以卡片的文件和页码自行构造来源编号。

## 4. 其他页面

### 4.1 分析成果（图表）

- 页首增加结果总数、图表类型分布和筛选状态摘要，只依据 `getCharts()` 返回的 `ChartData` 计算。
- 图表卡片统一显示标题、图表类型、已有元信息和数据表切换；不承诺公司、年度、问题来源等接口未返回的数据。
- 空状态提供“从研究工作台发起图表类问题”的明确引导。

### 4.2 资料库（知识库）

- 保留上传、删除、索引状态和表格能力。
- 增强资料库概览、上传状态、空状态和错误状态的视觉层级。
- 首期只显示现有 `filename`、`size_mb`、`upload_time`、`indexed` 字段；公司、年度、章节、页数、最近引用次数需要独立后端数据契约后再实施。

### 4.3 分析流程（DAG）

- 面向高级用户，页首说明流程用于解释“系统如何组织工作”，不与最终结论并列竞争注意力。
- 复用已有 `DagTaskSummary`、`DagExecutionTimeline`、`DagFlow`，统一颜色、状态标签与工具名称。
- 在窄屏隐藏复杂画布，优先呈现任务摘要和执行批次。

### 4.4 系统状态

- 保留只读边界。
- 将多个 `Descriptions` 卡片重组为“研究可用性”“模型与检索”“运行配置”三个层级。
- 状态颜色只表达健康、警告、失败，不能使用品牌色代替语义。

## 5. 设计系统规范

### 5.1 主题模式与主体色

主体色切换是纯前端外观偏好，和研究上下文完全隔离：不请求后端、不改变路由、会话、问答或检索参数。切换通过 `appStore` 同步更新 Ant Design `ConfigProvider` token 与页面 CSS 变量，交互后立即生效。仅允许下列两套已固定的色板：

| 选项 | 亮色主题主色 | 暗色主题主色 | 默认 |
|---|---|---|---|
| 金融青绿 | `#0F766E` | `#2DD4BF` | 是 |
| 深蓝 | `#1D4ED8` | `#60A5FA` | 否 |

在 `HeaderBar` 提供唯一的“外观”弹出面板，包含亮/暗模式和两个带文字标签的主体色色板；色板使用真实按钮、可见焦点、`aria-pressed` 和文字名称，不能仅靠色块区分。侧边栏不再保留独立主题开关，避免同一偏好出现两个不一致的编辑入口。已验证主体色与对应背景的对比度：亮色金融青绿/深蓝对暖白分别为 5.47:1/6.70:1，暗色高亮主体色对深色画布分别为 9.38:1/6.87:1。外观偏好可以沿用现有主题偏好的浏览器持久化机制，但必须使用受限枚举值并在应用首帧前完成读取，避免短暂显示默认色。研究上下文仍在刷新后重置。

主题配置必须在现有 `ConfigProvider` 树内原位更新，不能给 `AppLayout`、`Outlet`、`ChatContainer`、当前会话或消息列表添加随主体色变化的 `key`。因此外观切换不得关闭或重建 SSE 连接，不得丢失输入框草稿、当前消息、滚动位置或流式打字状态。

### 5.2 Token

| 类别 | 默认研究画布 | 深色专注模式 |
|---|---|---|
| 画布 | 暖白/浅灰，不使用渐变底图 | 深石墨/深蓝灰 |
| 主强调 | 用户选定的金融青绿或深蓝 | 对应高亮主体色 |
| 文字 | 深灰蓝、次级中灰 | 高对比浅灰、次级灰 |
| 边界 | 低对比中性边框 | 低亮度分割线 |
| 卡片 | 白底、细边框、轻阴影 | 深层级面板、细边框 |
| 语义色 | 成功绿、警告琥珀、错误红、信息蓝 | 保持语义一致并调高对比 |

第一期在 `theme.ts` 和 `global.css` 集中定义 token；`lightTheme`/`darkTheme` 改为接收主题模式和主体色的工厂配置，`AppLayout` 将品牌 CSS 变量同步到页面。所有品牌相关的马卡龙硬编码（当前至少 59 处，含图表、DAG、消息、页面和全局 CSS）必须迁移为 token 或派生色；`var()` 的紫色回退值也必须移除。成功、警告、错误、信息等语义色以及多序列图表的类别色保持独立，不得因主体色切换改变含义。

### 5.3 排版与布局

- 8px 基础间距；页面间距 24/32px；组件内部 8/12/16px。
- 桌面主内容最大宽度不超过 1440px；阅读答案列控制在 760px 左右。
- 标题采用 28/20/16 三层；正文 14/16px；数据/KPI 使用等宽字体和清晰的单位。
- 圆角统一为 8/12px；悬浮只允许 2px 位移和 150–250ms 过渡。

### 5.4 状态与可访问性

- 文字和交互状态满足 WCAG AA 对比度目标。
- 所有图标按钮提供可访问名称和键盘焦点。
- 贯彻 `prefers-reduced-motion`；禁止持续、无意义的背景动画。
- 不能只依赖颜色表示成功、警告或错误。

## 6. 响应式与性能

| 断点 | 行为 |
|---|---|
| ≥1440px | 主画布 + 证据面板，完整工作台 |
| 1200–1439px | 默认主画布与较窄证据侧栏并列；用户可按需将证据侧栏收起为抽屉，顶栏保留内联研究摘要 |
| 768–1199px | 侧栏默认收起，顶栏将只读研究摘要收纳为上下文按钮，图表和 KPI 双列或单列自适应 |
| <768px | 单列阅读，底部固定输入，分析过程、来源和只读研究摘要分别以可关闭的底部抽屉打开，彼此不叠加 |

- 延续现有路由懒加载；图表页面继续按需加载。
- 仅在可见时渲染大型图表/DAG；不在首页预加载所有分析页。
- 对流式回答保持滚动位置、加载和错误恢复的现有行为。

## 8. 视觉验收方法

每个工作包在现有开发环境中以 1440、1024、768、375 宽度进行截图对比；首期不为此新增浏览器自动化框架或依赖。验收不是主观地追求“炫”，而是检查：研究上下文是否连续、结论是否优先、证据范围是否如实表达、状态是否清晰、长文是否易读。

## 9. 证据驱动研究 Copilot 整体母版（后续实施方向）

### 9.0 C7.3 结构化比较事实契约

回答级多公司比较只读取人工核验的受限事实注册表，不读取 `data/charts`、LLM Markdown、KPI 正则或检索排序分数。首批事实集限定为 2024 年三大运营商的“营业收入”，每条记录必须具备：`fact_id`、`metric_key`、`metric_label`、`fiscal_year`、`company_name`、`value`、`unit`、`source_file`、`pages`、`excerpt`。`value` 与 `unit` 是已统一的展示口径，`excerpt` 必须来自登记的官方年报文本且受长度上限约束。

比较 API 仅在请求的指标、年度和公司集合均有注册事实时返回比较结果及逐项来源；任何未登记指标、年份或公司均返回明确的不可用状态，前端不渲染空壳比较工作区。回答关联以查询参数和返回的 `fact_id` 列表为准，不以模型答案内的数字或来源编号推断。首期不自动抽取或批量扩充事实，新增事实必须经过原文、页码和单位的人工核验并另行测试。

### 9.1 视觉取舍

三张概念稿中，深色分析驾驶舱适合高密度图表和状态观察，浅色投研报告适合长文本和表格，AI 原生研究 Copilot 最符合当前问答、证据、过程和追问能力。因此采用以下组合，而不是复制任一概念稿：

- 默认浅色：暖白研究画布、深蓝正文和金融青绿强调；沿用投研报告的克制排版。
- 可选深色：保留现有深色模式，服务图表、DAG 和夜间专注分析；不强制所有用户默认进入深色。
- 工作流：以 AI 原生研究 Copilot 的“问题—结论—财务证据—来源—追问”闭环为主，不把首页变为传统 BI 总览。

### 9.2 首页桌面母版

```text
全局侧栏 | 顶栏：面包屑、研究范围、模型/健康状态、外观、会话操作
---------+----------------------------------------------------------------
         | 主研究区（约 58%）                  | 研究侧栏（约 42%）
         | 当前会话 / 最近提问                 | 标签：证据 | 分析过程
         | 最终回答与回答级引用                | 来源文件、已有页码、检索匹配度
         | KPI、已有图表、结构化数据入口       | 缺失证据与风险提示、受控过程摘要
         | 固定追问输入区与已有快捷问题        | 窄屏时收纳为互斥抽屉
```

1. 主区以最终回答为阅读主线。最近提问只在当前会话确有用户消息时显示；空会话继续使用欢迎区，不能虚构研究标题。KPI 是当前回答文本的既有前端识别结果，继续保持原样和中性语义；图表页当前没有回答—图表关联，首期只能提供“前往分析成果”的全局入口，不能表示图表由当前回答生成。
2. 右侧栏首期只有“证据”和“分析过程”两个按需标签，默认“证据”；`Process` 继续复用安全 `AnalysisTraceStep`。概念稿中的 `Signals` 需要结构化风险/假设数据契约，本期不渲染、不以数值推导投资信号，也不以普通错误消息伪装研究信号。
3. 顶栏的公司/模式摘要仍是“下次提问条件”，不反向标记历史消息。没有明确公司时显示中性“未限定公司”，而不是占位的上市公司名称。
4. 没有来源时，证据栏显示真实空状态和如何获得来源的说明；不渲染虚构文档预览、页码、置信度或引用摘录。
5. “导出、分享、保存研究”不出现在首期操作栏，除非后端持久化与授权契约单独完成。
6. 当前页面已有检索配置栏和会话栏。P1 必须将其收敛为“页面顶端唯一研究配置入口 + 按需会话入口”，不能在现有两栏之外再增加永久研究侧栏，避免桌面端出现全局导航、配置、会话、主区、证据五栏并列。
7. 当前 RAG 与 Agent SSE 均可提供回答级来源；Agent 仅在实际 retrieve 工具收集到来源时携带来源。没有来源时，Agent 仍显示专属真实空状态，不能复用上一条回答来源，也不能基于过程摘要生成来源。任一在途请求（RAG Promise 或 Agent SSE）期间均禁止新建、切换和删除会话，直至请求正常结束、失败或取消，避免异步回调更新错误会话。前端不能仅依赖该禁用态：发起请求时必须捕获 `requestSessionId` 与 `requestId`，消息、过程、超时和错误写入均显式定位到 `requestSessionId`；回调仅在 `requestId` 仍有效时执行，绝不由 Store 在回调时读取 `currentSessionId` 决定写入目标。
8. 桌面主回答区只显示紧凑的引用数量和“查看证据”入口；完整 `SourceCard` 仅在研究侧栏显示，避免同一来源在消息内和侧栏重复占据阅读空间。
9. `ChatPage` 维护仅当前会话有效的 `activeEvidenceMessageId`：默认选择最后一条助手回答；用户点击任一历史回答的“查看证据”时切换该选择。切换/删除会话或该消息不存在时重置选择，侧栏绝不从其他会话或上一条回答继承来源。
10. 公司范围的唯一运行期来源是 `appStore.researchContext.companyName`：`ChatPage` 直接订阅它作为选择控件值，编辑后只通过 `setResearchContext` 写回；不得再以本地 `selectedCompany` 初始值或挂载副作用覆盖 Store。刷新后公司范围自然重置。`agent-mode` 是现有浏览器偏好：Store 创建时读入并投影到 `researchContext.mode`，因此直接进入任意路由时顶栏即正确；用户切换时同步更新偏好和投影。请求始终使用该同步后的当前模式，不能出现“顶栏、开关与请求参数各自不同”的状态。`agent-max-steps` 保留现有浏览器偏好机制，`topN` 仍只属于当前页面高级选项；公司范围、模式、步数和 `topN` 均不写入 `chat-sessions`。`activeEvidenceMessageId` 同样只在组件运行期存在。

### 9.5 交互、响应式与性能约束

- ≥1200px：主区与研究侧栏并列；侧栏标签切换不影响主区滚动和流式连接。
- 768–1199px：证据和过程由同一个可访问触发器打开，任一时刻最多一个抽屉；会话抽屉与研究侧栏也必须由 `ChatPage` 的同一受控状态管理并互斥，避免遮挡固定输入区。
- <768px：回答、KPI、图表单列；输入区保持安全区域；来源/过程从回答附近的触发器按需打开，不能永久占据屏幕。
- 不预加载图表中心或 DAG；只在消息已有数据且区域可见时渲染重型可视化。
- 禁止依赖动画来表达完成状态；应用 `prefers-reduced-motion` 时取消非必要过渡。
- 唯一研究配置入口必须是原生按钮或 Ant Design `Button`，提供可访问名称、键盘操作和展开状态；不得保留只通过鼠标 `div onClick` 打开的配置折叠区。
- 证据/过程标签使用真实 `tablist`、`tab`、`tabpanel` 语义及方向键/焦点行为；切换标签、关闭抽屉和外观切换均不得导致流式请求切换会话或写入其他会话。
- 用户点击全局路由离开工作台时，先使发起请求的 `requestId` 失效，再取消当前 RAG 请求（通过现有 HTTP 客户端支持的 `AbortSignal` 贯通到 `queryQuestion`）、关闭 SSE、清理轮询和超时计时器并恢复非加载状态；所有 RAG 与 SSE 回调均先校验 `requestId`，不显示“成功完成”或向已离开的会话补写内容。取消错误（例如 Axios `ERR_CANCELED`）是预期控制流，不能转化为“服务不可用”系统消息。若请求已不可取消，仍以该标识阻止完成回调写入 Store。`prefers-reduced-motion` 下自动滚动改为即时滚动。

### 9.6 不纳入本次方案的视觉承诺

- 概念稿中出现的公司名、财务数值、页面摘录、评级、置信度和风险信号均为视觉示意，不能照搬到真实界面。
- 自定义字体、文档 PDF 高亮预览、跨会话研究项目、报告导出/分享、团队协作和新型金融指标，均需要独立数据或产品决策后再规划。

## 10. C9 研究报告画布

### 10.1 桌面信息层级

```text
轻量问题气泡
        ↓
研究报告卡片
  研究上下文：范围 / 模式 / 耗时 / 证据数
  研究结论：回答正文
  财务事实：已存在 KPI；已核验比较仅在回答携带时出现
  证据入口：打开该回答的证据包
  执行摘要：安全过程步骤数与按需展开入口
```

助手回答占用主阅读列，不能继续限制为主区的 70%；用户问题仍保持紧凑、右对齐。历史消息若没有 `researchMeta`，保持兼容的普通回答呈现，不向其补写范围、模式或耗时。

桌面只在已有“全局导航 + 会话列 + 主阅读列 + 证据侧栏”的四层结构中调整阅读比例，不再新增常驻面板；≥1200px 主阅读列的报告卡片最大宽度为其可用宽度，证据侧栏保持现有固定宽度。1024px 已按既有响应式规则隐藏右侧栏，阅读列独占可用空间，证据仍由现有按需抽屉打开。

### 10.2 证据包

来源仅能按 `(company_name, source_file)` 聚合。组内：

- 页码取现有来源页码去重后的升序集合；
- 摘录逐条保留在展开区，不将多个摘要拼接为模型未见过的新引用；
- 组内来源编号保留，以便与回答中的现有 `[来源N]` 一致；
- 分组标题只说明证据类别，绝不汇总分数；每条来源仅在自身具有数值 `scores.hybrid` 时显示“检索匹配度”。组内全部没有数值分数时，标题显示“回答证据”，不显示空分数占位。
- 有数值 `hybrid` 的分组标题显示“检索证据 · N 条”，不能把来源数量写成“检索匹配度”；数值匹配度只在展开后的单条来源中呈现。

聚合只是阅读层组织，不能改变写入会话的原始 `Message.sources`，也不能把来自其他回答的来源合并进来。

### 10.3 组件与数据职责

| 组件 | 责任 | 不得承担的责任 |
|---|---|---|
| `MessageBubble` / `ResearchAnswerCard` | 根据当前 `Message` 呈现研究报告层级与已存在区块 | 不解析或生成新的财务事实 |
| `EvidenceContent` / `EvidenceBundle` | 对当前选择回答的来源作阅读层聚合 | 不改变来源归属、分数或页码 |
| `SourceCard` | 显示单条来源的摘录与原始评分详情 | 不把非数值评分变为百分比 |
| `AnalysisTraceContent` | 呈现已安全投影的执行摘要 | 不显示 thought 或原始工具内容 |

### 10.4 实施顺序

1. 为助手报告卡片、旧消息兼容、聚合证据、无分数 Agent 标签、来源选择隔离写 RED 测试。
2. 实现回答画布与桌面阅读宽度，保留用户气泡与现有输入、会话交互。
3. 实现证据聚合阅读层和可访问的折叠/展开。
4. 回归 Agent/RAG、来源选择、取消、窄屏抽屉与已有已核验比较卡片。
5. 在用户实际桌面浏览器完成 1440 与 1024 宽度视觉验收。

### 10.5 交互与可访问性补充

- 证据组的展开/收起使用原生 `button` 或 Ant Design 受控按钮，必须有可见焦点、`aria-expanded` 和清晰名称；不能以仅鼠标可点击的 `div` 作为新交互入口。
- 报告卡片不复制现有右侧的完整来源卡片，只保留“查看证据”入口；右侧栏仍是唯一完整来源阅读位置。
- 仅在 `researchMeta` 存在时使用报告样式。用户消息、系统消息和旧助手消息均保持原有结构，避免桌面视觉改造改变错误提示、复制、重试、流式光标或会话选择交互。
- C9 不修改 API、SSE、`chatStore` 写入时序或会话持久化字段；只读取现有 `Message` 数据。新的来源分组为纯派生结果，测试必须覆盖“切换所选回答后不残留前一回答来源”。
- 本轮触及的报告卡片、来源分组和单条来源样式统一使用现有主题语义变量或 `colors` token，不以紫色渐变、状态色或硬编码数字颜色伪造“金融感”。

## 11. C10 按需证据工作栏

### 11.1 桌面行为

默认布局为全局导航、会话列和全宽主阅读列。用户点击回答的“查看 N 条证据”或研究摘要条“查看证据”后，`ChatPage` 才在右侧挂载 340px 的证据工作栏；它展示当前选中回答的证据/分析过程标签，并提供“关闭证据栏”按钮。关闭只改变阅读布局，不修改 `activeEvidenceMessageId`、会话或消息。

顶部入口默认选择当前会话最后一条助手回答；历史回答入口先更新选中消息，再打开工作栏。若宽度小于 1200px，两个入口继续调用已有互斥 `EvidencePanel` Drawer，不能同时显示工作栏和 Drawer。

### 11.2 视觉收口

- 用户问题气泡从紫色渐变收敛到当前主体色，避免与金融青绿/深蓝外观产生双品牌冲突。
- 报告卡片维持暖白画布、轻边界和有限强调；证据栏只在用户核查时出现，避免空白时形成视觉噪音。
- 不改变财务对比卡的数据顺序、单位、页码或任何数值展示。

## 12. C11 已核验比较正文一致性

事实注册表是三大运营商 2024 年营业收入的唯一真值来源。RAG 在完成原有检索和上下文构建后，先查询注册表：若问题命中完整比较事实，则不再调用 LLM 生成该问题的正文，而使用注册表项目按固定顺序输出公司、统一值、单位、文件和页码；返回结构中的 `comparison` 继续复用同一对象。这样正文和比较卡片从同一不可变事实集合派生，避免任何单位换算分叉。

未命中注册表的问题不改变：继续选择既有 Prompt 并调用模型。C11 不从检索文本重新解析单位，也不把注册表扩展为通用计算器；来源摘要仍来自本次实际进入上下文的检索结果。

## 13. C12 正文引用与证据工作栏联动

`MessageBubble` 仅将当前回答 `sources` 内存在的 `[来源N]` 转换为带 `data-source-index` 的可访问按钮。事件由消息组件显式上抛 `(messageId, sourceIndex)`，`ChatPage` 因而能够同时选择该回答、记录高亮来源编号并复用既有桌面工作栏或窄屏 Drawer。

`EvidenceContent` 只从传入来源构建证据组：收到高亮编号时自动展开包含该来源的组，为对应 `SourceCard` 添加短暂视觉高亮和可定位标记，并将卡片滚动至可见区域。编号不在当前回答来源中时不打开或高亮任何来源。关闭工作栏、切换会话或普通“查看证据”入口清除高亮编号。
