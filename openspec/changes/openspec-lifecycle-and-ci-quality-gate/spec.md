# 规格：OpenSpec 生命周期收口与 CI 质量门禁

## 要求：已完成变更归档

已完成且无实际阻塞项的 OpenSpec 变更必须从活动目录归档，且文件内容不得丢失。

### 场景：审核完成变更

- **当** 审核活动变更的任务清单和 TDD 状态
- **则** 仅任务完成、验证记录齐全且无未解决文件的变更可以归档

### 场景：提示词备份收口

- **当** 审核 `prompt-injection-guard` 的 `.py.bak` 清理项
- **则** 仅在确认预期备份文件不存在或获得删除确认后，才可以关闭该项

### 场景：归档后活动目录

- **当** 完成归档
- **则** `openspec/changes/` 根目录只保留真实未完成变更，已归档变更可在 `archive/` 中完整访问

## 要求：基础质量门禁

GitHub Actions 必须在不使用真实服务密钥的条件下验证后端和前端。

### 场景：后端质量任务

- **当** 对 main 推送或创建目标为 main 的拉取请求
- **则** CI 使用 Python 3.11 安装锁定依赖、编译 `src` 并运行白名单 pytest 测试
- **且** 不发起 DashScope、LangSmith 或本机 HTTP 请求

### 场景：前端质量任务

- **当** CI 运行前端任务
- **则** CI 使用 Node 20 执行 `npm ci`、Vitest 和生产构建

### 场景：工作流隔离

- **当** 质量门禁失败
- **则** 工作流不会推送镜像、部署服务或读取部署 Secrets

## 要求：发布门禁前置条件

当项目选择将 Quality Gate 作为镜像发布门禁时，Docker 构建必须只消费已通过 Quality Gate 验证的提交，且 main 必须配置必需状态检查。

### 场景：质量失败

- **当** 某个提交的 Quality Gate 失败
- **则** 该提交不得触发自动 Docker 镜像推送或服务器自动部署

### 场景：质量通过

- **当** main 上的提交通过 Quality Gate
- **则** Docker 构建只使用该已验证提交的 SHA 构建和标记镜像
