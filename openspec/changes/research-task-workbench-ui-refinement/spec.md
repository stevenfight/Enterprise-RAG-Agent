# 规范：研究任务工作台界面收口

## 需求：任务导航与详情层级

### 场景：任务列表与当前任务并列呈现

- **当** 研究任务列表成功返回一个或多个任务
- **则** 页面显示任务列表数量、每个任务的任务 ID 和已有状态/审批/报告摘要
- **并且** 当前任务详情位于任务导航之后的主从详情区域中
- **并且** 不新增接口请求或本地推断字段

### 场景：没有任务

- **当** 研究任务列表为空
- **则** 继续显示“当前没有可查看的研究任务”空态
- **并且** 不显示任务详情、执行进度或报告伪数据

## 需求：响应式工作台

### 场景：窄屏查看研究任务

- **当** 视口宽度小于等于 768px
- **则** 任务导航与详情按单列顺序排列
- **并且** 任务 ID、状态标签和操作按钮允许换行
- **并且** 页面不因本次布局新增横向溢出

## 需求：真实交付空态

### 场景：报告尚未持久化

- **当** 报告接口返回 404
- **则** 显示“该任务尚未生成可查看的持久化报告”
- **并且** 证据与图表区域明确说明只展示已持久化内容

## 需求：可访问性

### 场景：键盘与辅助技术访问

- **当** 用户使用键盘浏览任务工作台
- **则** 主地标、工作台区域、任务选择按钮和刷新按钮具有稳定的可访问名称
- **并且** 选中任务按钮通过 `aria-pressed` 表达当前选择
- **并且** 既有审批、裁决、签发按钮的可访问名称和加载态保持不变
