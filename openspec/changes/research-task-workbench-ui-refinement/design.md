# 设计：研究任务工作台界面收口

## 设计判断

这是一个需要完成操作的企业工作台，采用 impeccable 的 Operate 模式。页面的主路径为：

```text
任务导航 → 选择任务 → 读取状态与执行证据 → 进行审批/裁决/签发
```

不把页面改造成营销式仪表盘，也不添加大号指标模板。现有马卡龙主题、Ant Design 组件和页面标题保持不变。

## 布局

- 桌面端使用 `research-task-workbench` 主从网格：左侧为任务列表与提交入口，右侧为所选任务详情。
- 详情区域继续按 DOM 顺序展示任务详情、执行 DAG、执行进度、报告、冲突、证据和图表；DAG 与执行进度可在宽屏并列，报告与冲突保持完整宽度。
- 移动端在 768px 以下切换为单列，任务列表先于详情，交互按钮保留可点击尺寸和键盘焦点。
- 任务列表条目使用统一的 `research-task-row` 语义样式：主行显示任务 ID，次行显示状态、审批和报告版本，选中态只使用主题色与背景层级表达。

## 文案与状态

- “任务列表”旁显示当前列表数量，数量来自实际 `tasks.length`，不推断业务统计。
- 创建入口使用“提交新研究任务”标题和简短说明，说明提交后会进入审批流程。
- 报告证据与报告图表保留子组件的真实空态，并在外层说明“仅展示服务端已持久化内容”，避免用户误解为数据加载失败或报告缺失。
- 错误、加载、权限和审批按钮继续沿用既有文案与状态变量，避免改变业务语义。

## 样式约束

- 仅增加页面作用域 CSS 类，不修改全局色板和共享组件契约。
- 不使用 emoji 或 Unicode 字符替代图标，不增加装饰性动画。
- 通过既有 CSS 变量表达主题色、边框、表面和文字颜色；状态色仍由 Ant Design `Tag` 语义色负责。
- 使用现有 16px/24px 间距节奏，移动端收紧为 16px 页面间距。

## 数据边界

所有新增文案和布局只消费已有 `tasks`、`selectedTask`、`report`、`conflicts` 和现有权限状态。不得从任务 ID、报告文件名或正文推测公司、年份、可信度、数量或研究结论。
