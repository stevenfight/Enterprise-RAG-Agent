# 变更提案：研究任务工作台界面收口

## 背景

研究任务页已经具备任务提交、审批、执行摘要、报告、冲突裁决和报告签发能力，但当前页面将所有区域纵向堆叠在同一条卡片流中。用户在任务列表、当前选中任务和报告核验之间来回滚动，无法快速建立“选择任务—查看状态—执行处置—核验交付”的工作路径。

## 目标

- 保留现有研究任务接口、权限判断、轮询和操作语义，仅优化页面信息架构与视觉层级。
- 在桌面端形成清晰的任务导航与详情主从布局，在移动端自动回落为单列阅读顺序。
- 让任务列表条目同时表达任务标识、运行状态、提交审批和报告可用性。
- 为报告、证据和图表的真实空态补充可理解的上下文，不生成接口未返回的内容。
- 保持现有马卡龙/企业研究视觉语言，不引入新依赖、后端字段或服务器变更。

## 非目标

- 不改变研究任务数据模型、API 请求、权限模型、轮询周期或审批流程。
- 不新增模拟统计、研究结论、证据、图表数据或报告内容。
- 不改动其他页面，不调整部署目录、容器、Nginx 或 `main` 分支。

## 成功标准

- 研究任务页在桌面端可同时看见任务导航和当前任务详情；窄屏不出现页面级横向溢出。
- 任务列表、详情、执行进度、报告、冲突与证据区的阅读顺序与 DOM 顺序一致。
- 既有页面测试、可访问性测试、前端构建与静态检测通过。
