# 设计：研究报告可发现性

## 服务端列表契约

在已有研究任务快照中增加可选 `report` 摘要：

```json
{
  "report": {
    "report_version": 1,
    "review_status": "pending_review"
  }
}
```

摘要由当前报告仓储读取，只有存在最新报告时返回；不返回声明正文、事实 ID 或来源内容。任务详情、创建响应和列表响应复用同一快照序列化逻辑。

## 前端行为

- `Sidebar` 保留现有菜单顺序，在知识库管理后加入“研究任务”。
- 任务按钮显示“有报告 vN”标记，帮助用户区分历史无报告任务。
- 首次加载任务列表时，若当前选择无效，选择第一项有报告的任务；若没有任何报告，再回退到第一项并保留原有空态。
- 报告正文仍通过既有 `/tasks/{task_id}/report` 按选中任务读取；404 继续显示“该任务尚未生成可查看的持久化报告”。

## 验证边界

- 后端验证列表只返回报告摘要且无报告任务不产生 `report` 字段。
- 前端验证菜单入口、报告标记和默认选择。
- 不以本地未提交代码证明服务器已部署；服务器发布需要后续独立候选提交、构建和部署授权。
