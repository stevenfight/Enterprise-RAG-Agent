# 设计：财务研究工作台 UI 改造

## 1. 产品定位与设计原则

产品定位为“企业年报研究助手”，而不是通用聊天机器人或交易终端。设计语言采用：

- 默认浅色研究画布：服务年报阅读、长回答和证据核验。
- 可选深色专注分析模式：服务图表、DAG 和高密度分析，不作为强制默认。
- 单一品牌强调色：深蓝或金融青绿；涨跌、警告、错误只使用语义色。
- 结论优先、证据紧随、过程按需展开；避免同权重的卡片堆叠。
- 数字使用现有等宽字体栈，正文保持清晰中文无衬线字体。

不采用当前“马卡龙 + 大面积渐变 + 玻璃拟态”作为主视觉。圆角、阴影和渐变只用于层级区分，不能替代信息组织。

## 2. 信息架构

全局一级导航保留五个能力入口，但改用研究语言：

| 现有路由 | 新名称 | 主要职责 |
|---|---|---|
| `/` | 研究工作台 | 发起问题、阅读结论、核验证据、查看任务进度 |
| `/charts` | 分析成果 | 浏览已有图表与数据表，不承诺保存研究报告 |
| `/knowledge` | 资料库 | 管理可用年报和索引状态 |
| `/dag` | 分析流程 | 高级用户查看任务规划与执行批次 |
| `/settings` | 系统状态 | 查看模型、向量库、记忆和工具状态 |

所有页面在顶栏或页首显示统一的研究上下文。`HeaderBar` 在桌面端展示只读的“下次提问范围”和模式摘要，并继续复用 `AppLayout` 的 `checkHealth()` 结果显示“检查中/已就绪/暂不可用”；首页的 `ResearchContextBar` 是唯一可编辑入口。首期在现有 Zustand 前端 Store 中新增会话级 `researchContext`，同步公司范围和模式到各路由；它只在当前应用运行期间共享，刷新页面后按现有前端状态策略重置，不接入 `localStorage`、`sessionStorage` 或后端持久化，也不伪造跨设备研究项目。`topN` 和 `agentMaxSteps` 保持为首页高级选项，不进入跨路由上下文。

已有聊天会话会按现有机制保存在浏览器中，因此研究上下文只能表述为“下次提问条件”，不得为历史消息补写或推断公司范围、模式。历史问答必须保持其原有内容，不以当前 `researchContext` 标记其检索条件。

## 3. 首页：研究工作台

桌面端采用“主画布 + 可收起证据面板”的双栏，不新增第三个永久导航栏：

```text
全局导航 | 顶栏：研究范围 / 系统状态 / 主题
---------+------------------------------------------------
         | 研究摘要条：公司范围、模式、当前会话、数据提示
         |------------------------------------------------
         | 主研究画布                    | 证据与过程面板
         | - 欢迎与研究模板              | - 来源文件与页码
         | - 问答与流式结论              | - 检索融合分说明
         | - KPI 重点指标                | - 工具调用、观测摘要
         | - 图表/引用入口                | - 待核验提示
         |------------------------------------------------
         | 固定输入区：提问、公司范围、Agent 开关
```

### 3.1 组件映射

| 新组件/区域 | 复用或改造来源 | 数据边界 |
|---|---|---|
| `ResearchContextBar` | `ChatPage` 的公司选择、Agent 开关、会话状态 | `getCompanies`、本地会话状态 |
| `ResearchWelcome` | 示例问题和 `ChatContainer` 空状态 | 仅静态研究模板与已有公司列表 |
| `ResearchAnswerCanvas` | `MessageBubble`、`FinancialKPICards` | 现有问答响应和消息 Store |
| `EvidencePanel` | `SourceCard` | 回答级 `SourceInfo.source_file`、`pages`、`scores`；分数标注为“检索匹配度”，不声明 KPI 逐项引用 |
| `AnalysisTracePanel` | `ThoughtChainDrawer` | 仅展示工具名称、输入摘要、观测摘要、耗时和完成状态 |
| `ResearchComposer` | `ChatInput` | 保留 Enter/Shift+Enter 与流式禁用逻辑 |

### 3.2 分析过程约束

当前 `ReasoningStep` 包含 `thought`、`action`、`observation`。首期界面只向用户展示：

- 操作名称和简化后的输入条件；
- 可核验的检索/工具观察结果；
- 步骤序号、耗时、完成/警告状态；
- 强制停止或缺少证据时的风险提示。

不得把 `thought` 文本作为产品内容展示。现有 `MessageBubble` 内嵌步骤预览和 `ThoughtChainDrawer` 都必须重构：抽屉重命名为“分析过程”，两处均移除内部思维文本区域。

`action_input` 和 `observation` 也不能原样透传到界面。实现时应按工具类型采用允许展示字段清单、长度上限和敏感键名脱敏；密钥、令牌、授权信息、请求头、运行配置、文件绝对路径、堆栈及无法归类的原始输入均不得展示。没有可安全展示的内容时，只显示工具名称、步骤状态和“未提供可展示摘要”。

安全投影必须发生在 SSE 事件写入消息 Store 之前，而非仅在组件渲染时隐藏。`chatStore` 持久化前只保存安全的过程视图模型：单 Agent 丢弃 `thought`，多 Agent 丢弃 `step_type = thought` 的内容，仅保留 Worker 名称、状态、已完成步骤数和耗时。加载旧 `chat-sessions` 时需清理遗留的内部思维、原始输入和原始观测字段；用户消息与最终回答不受影响。

### 3.3 财务数字与证据语义

- KPI 必须按现有解析结果原样显示 `value` 和 `unit`；首期不得在前端换算单位、合并口径、补全币种或推导同比。
- 收入、利润、ROE、毛利率等普通财务数值采用中性正文色，不因数值为正而显示为“利好”；只有解析器明确标记方向的增长类指标才可使用上涨/下跌语义色，并同时提供箭头和文字。
- 现有 `SourceInfo` 只能作为回答级证据。首期可在答案旁展示来源文件、页码和“检索匹配度”，但不得声称某一 KPI 已有逐项来源映射；该能力需要后端返回可靠的指标—来源关联后另行设计。

## 4. 其他页面

### 4.1 分析成果（图表）

- 页首增加结果总数、图表类型分布和筛选状态摘要，只依据 `getCharts()` 返回的 `ChartData` 计算。
- 图表卡片统一显示标题、图表类型、已有元信息和数据表切换；不承诺公司、年度、问题来源等接口未返回的数据。
- 空状态提供“从研究工作台发起图表类问题”的明确引导。

### 4.2 资料库（知识库）

- 保留上传、删除、索引状态和表格能力。
- 增强资料库概览、上传状态、空状态和错误状态的视觉层级。
- 首期只显示现有 `filename`、`size_mb`、`upload_time`、`indexed` 字段；公司、年度、章节、页数、最近引用次数需要独立后端数据契约后再实施。

### 4.3 分析流程（DAG）

- 面向高级用户，页首说明流程用于解释“系统如何组织工作”，不与最终结论并列竞争注意力。
- 复用已有 `DagTaskSummary`、`DagExecutionTimeline`、`DagFlow`，统一颜色、状态标签与工具名称。
- 在窄屏隐藏复杂画布，优先呈现任务摘要和执行批次。

### 4.4 系统状态

- 保留只读边界。
- 将多个 `Descriptions` 卡片重组为“研究可用性”“模型与检索”“运行配置”三个层级。
- 状态颜色只表达健康、警告、失败，不能使用品牌色代替语义。

## 5. 设计系统规范

### 5.1 Token

| 类别 | 默认研究画布 | 深色专注模式 |
|---|---|---|
| 画布 | 暖白/浅灰，不使用渐变底图 | 深石墨/深蓝灰 |
| 主强调 | 深蓝或金融青绿，二选一后固定 | 同色提高亮度 |
| 文字 | 深灰蓝、次级中灰 | 高对比浅灰、次级灰 |
| 边界 | 低对比中性边框 | 低亮度分割线 |
| 卡片 | 白底、细边框、轻阴影 | 深层级面板、细边框 |
| 语义色 | 成功绿、警告琥珀、错误红、信息蓝 | 保持语义一致并调高对比 |

第一期在 `theme.ts` 和 `global.css` 集中定义 token；组件不得继续散落硬编码的马卡龙色值。

### 5.2 排版与布局

- 8px 基础间距；页面间距 24/32px；组件内部 8/12/16px。
- 桌面主内容最大宽度不超过 1440px；阅读答案列控制在 760px 左右。
- 标题采用 28/20/16 三层；正文 14/16px；数据/KPI 使用等宽字体和清晰的单位。
- 圆角统一为 8/12px；悬浮只允许 2px 位移和 150–250ms 过渡。

### 5.3 状态与可访问性

- 文字和交互状态满足 WCAG AA 对比度目标。
- 所有图标按钮提供可访问名称和键盘焦点。
- 贯彻 `prefers-reduced-motion`；禁止持续、无意义的背景动画。
- 不能只依赖颜色表示成功、警告或错误。

## 6. 响应式与性能

| 断点 | 行为 |
|---|---|
| ≥1440px | 主画布 + 证据面板，完整工作台 |
| 1024–1439px | 证据面板可收起为抽屉，保留研究摘要条 |
| 768–1023px | 侧栏默认收起，图表和 KPI 双列或单列自适应 |
| <768px | 单列阅读，底部固定输入，分析过程和来源以底部抽屉打开 |

- 延续现有路由懒加载；图表页面继续按需加载。
- 仅在可见时渲染大型图表/DAG；不在首页预加载所有分析页。
- 对流式回答保持滚动位置、加载和错误恢复的现有行为。

## 7. 数据契约与依赖

| 能力 | 首期状态 | 现有来源/限制 |
|---|---|---|
| 公司范围 | 可实施 | `getCompanies()` |
| 问答、KPI、引用、页码 | 可实施 | `queryQuestion`、`streamAgentQuery`、消息 Store、`SourceInfo`；来源为回答级，分数只能标为检索匹配度 |
| 财务 KPI 语义 | 可实施 | 保留解析出的原始 `value`/`unit`；仅增长类可使用方向语义，普通数值保持中性 |
| 分析过程 | 可实施但需脱敏 | 仅允许展示脱敏后的 `action`、`action_input`、`observation` 摘要和状态 |
| 图表和类型筛选 | 可实施 | `getCharts()` / `ChartData` |
| 文档索引状态 | 可实施 | `getDocuments()` |
| 文档公司/年度/章节 | 不纳入首期 | 当前 API 未提供可靠字段 |
| 保存研究、可分享报告 | 不纳入首期 | 当前无持久化契约 |

## 8. 视觉验收方法

每个工作包在现有开发环境中以 1440、1024、768、375 宽度进行截图对比；首期不为此新增浏览器自动化框架或依赖。验收不是主观地追求“炫”，而是检查：研究上下文是否连续、结论是否优先、证据范围是否如实表达、状态是否清晰、长文是否易读。
