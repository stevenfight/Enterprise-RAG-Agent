# v7.0 计划三轮核查记录

> 本文件记录初版 A/B/C/D/E 方案核查；多模态升为必选 M 后的增量三轮核查见 `multimodal-revision-three-pass-review.md`。以下表述已同步到当前六阶段路线。

## 第一轮：范围完整性与定位一致性

### 核查范围

- 最终定位是否贯穿 proposal、roadmap、design、spec、tasks 和 TDD。
- 当前 A、B、C0、M、C1、D、E 七个工作包是否有输入、输出、依赖、退出门禁和非目标。
- 是否重复建设现有功能，是否存在仅为展示而增加的伪需求。

### 发现与修正

1. **无密钥 CI 缺少可执行输入。** 原方案写了“CI 运行核心评测”，但真实模型需要密钥。已增加受版本控制的固定回答、来源和工具轨迹夹具，并明确它只验证评测器与门禁，不冒充在线模型质量。
2. **审批范围存在过度设计风险。** 当前工具以只读和计算为主，原方案容易诱导新增虚构高风险工具。已将首版审批聚焦到关键冲突裁决和正式报告签发，未来存在真实写操作时再扩展。
3. **TDD 状态统计存在歧义。** 说明文字出现绿色 emoji，自动计数会得到一个伪 GREEN。已改为文字“绿色（通过）”，测试行保持全部 RED。

### 结论

第一轮修正后，范围与最终定位一致；延后项和非目标清晰，不再把无密钥回放结果与在线模型质量混淆。

## 第二轮：技术可行性与依赖顺序

### 核查范围

- 当前 Python 依赖、运行方式、存储能力、SSE 协议和 API 兼容性。
- 当前 A、B、C0、M、C1、D、E 的先后依赖是否存在循环或无法在当前工程落地的假设。
- 是否违反“不主动安装包”“不考虑 fallback”“保留既有函数逻辑”的项目规则。

### 事实核查

- Python 3.11.15，标准库 SQLite 3.51.2。
- 当前启动方式均为单 Uvicorn 进程，未配置 workers。
- `langsmith` 已安装但本地版本与 `requirements.lock` 声明存在差异。
- `openevals` 可以被解释器定位，但 `pip show openevals` 找不到包元数据，且不在锁文件。
- `aiosqlite` 可定位但未进入项目依赖清单。
- 当前 SSE 只发送 `data:`，没有标准 `id:`；现有即时 API 没有任务持久化。

### 发现与修正

1. **不可依赖环境偶然状态。** 首版核心不依赖 OpenEvals 或 aiosqlite；评测核心使用项目代码与 pytest，任务存储使用标准库 sqlite3。后续正式采用时再统一依赖声明。
2. **SQLite 承诺范围过宽。** 已限定首版单进程部署，并补充短事务、独立连接、WAL、busy timeout、异步线程执行和多 worker 前专项验收。
3. **检查点内容未约束。** 已规定只保存 schema 化 JSON、稳定 ID 和制品引用，禁止序列化线程、队列或 Agent 实例。
4. **恢复语义过窄。** 已从“有副作用工具不重复”提升为“所有已完成步骤和成功调用默认复用；有副作用调用绝不自动重复”。
5. **接口兼容与 fallback 冲突。** 新增独立持久任务 API，保留旧即时 API；持久任务路径失败后不静默切换 single/multi。
6. **指标依赖顺序错误。** A 阶段只能建立答案级证据基线；B 阶段形成 Claim/EvidenceBundle 后，才启用声明级 95% 硬门禁。

### 结论

第二轮修正后，方案可在当前 Windows、Python 3.11、单进程 FastAPI 架构上渐进实现，不要求立即安装新包，也不破坏原即时问答接口。

## 第三轮：验收、风险与求职展示价值

### 核查范围

- 指标是否可计算、可比较，目标值是否存在统计口径歧义。
- 数据集是否可能被简单样本灌水，人工复核是否存在虚假表述。
- 外部状态和可选交付是否会错误阻塞主线。
- 每个阶段能否形成可演示、可量化、可在面试中解释的成果。

### 发现与修正

1. **指标分母不明确。** 已新增 `acceptance.md`，定义数值正确率、声明级证据支持率、无依据声明率、拒答率、恢复率和重复执行数。
2. **100 条样本可能失真。** 已增加类别最低配额、公司/报告期/来源覆盖要求，并禁止只替换公司名凑独立覆盖。
3. **复核角色表述不严谨。** 已把“双人式复核”改为“编制与复核两阶段分离”；单人项目允许分轮执行，但不得伪称两名审核人。
4. **外部 CI 状态可能阻塞本地工作。** 现有质量门禁未闭环只阻塞 A3 工作流修改，不阻塞 A1/A2 数据与评测器开发。
5. **导出范围膨胀。** v7.0 只要求 Markdown/HTML；PDF、Word、Excel 改为后续独立 OpenSpec，不阻塞首发。
6. **100% 恢复容易被过度宣传。** 已明确仅指受控故障集，不代表生产环境绝不失败。

### 结论

第三轮修正后，方案具备明确指标、样本覆盖、阶段决策和求职交付，且避免把实验结果、单人复核和受控故障演练夸大为生产保证。

## 总结论

- 三轮均发现并修正了实质问题，不是形式化复读。
- 当前文档可以作为实施总纲，但尚未批准开发，TDD 必须保持全红。
- 推荐批准后仅启动 A 阶段，不并行开发 B、C0、M、C1、D、E。
