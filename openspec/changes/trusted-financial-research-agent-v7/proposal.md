# 变更提案：v7.0 可信金融研究 Agent 升级

## 背景

项目已具备混合 RAG、自研 ReAct、多 Agent DAG、流式输出、回答级证据链、LangSmith 追踪、基础评测脚本、Prompt Injection 防护和现代化研究工作台。继续增加普通页面、Agent 角色或模型接口，难以形成新的求职竞争力。

当前主要缺口是：质量缺少稳定可复现的金融评测基线；财务事实仍以少量硬编码注册表和文本证据为主；MinerU 虽已用 VLM 生成图片和表格产物，但这些视觉制品尚未形成可定位、可核验的事实证据；会话记忆不能恢复 DAG 执行；安全、成本与审批没有统一任务治理；研究结果尚未形成可审计交付闭环。

## 最终定位

将项目升级为：

> 可验证、可审计、可恢复，并能理解复杂财报文字、表格、图表与扫描页的金融研究 Agent 平台。

系统不仅回答财报问题，还能用结构化事实和确定性计算支撑结论，识别跨来源冲突，在中断后恢复复杂研究任务，并通过评测、权限、审批和审计控制质量与风险。

## 版本说明

- `openspec/project.md` 已将既有多 Agent 主线定义为 v6.0，因此本升级采用路线版本 v7.0。
- 当前 Git 标签为 v5.19。规划与实施期间不提前创建 v7.0 标签；只有全部必选门禁通过、版本记录完成并获得发布确认后才打标签。

## 目标

1. 建立可离线复现、可扩展、可比较的金融 Agent 评测系统和质量发布门禁。
2. 建立统一金融事实模型、单位与口径归一、确定性计算和冲突核验能力。
3. 复用现有 MinerU 与 PDF 数据链，建立表格、图表、扫描页、脚注和跨页结构的可验证多模态理解能力。
4. 建立任务级检查点、幂等工具调用、重试、暂停、恢复和人工审批能力。
5. 建立工具权限、风险分级、审计、安全测试和成本预算能力。
6. 将聊天式问答升级为计划、执行、审核、报告交付的研究工作流。
7. 形成可量化评测报告、视觉证据演示、故障演示和求职案例材料。
8. 建立源 PDF 不可变、派生产物可追踪、索引可回滚和声明可追溯的文档数据底座。

## 成功标准

以下阈值为首版建议值，A 阶段完成现状基线后允许在提案中留痕调整，不能静默降低：

- 金融黄金评测集不少于 100 条，核心高风险集不少于 30 条。
- 数值正确率不低于 98%。
- B 阶段形成结构化声明后，有依据声明的证据支持率不低于 95%；A 阶段先记录现有答案级基线，不提前把近似指标当作声明级指标。
- 无依据关键声明率不高于 3%。
- 应拒答样本的正确拒答率不低于 95%。
- 多模态专集不少于 40 个页级或区域级案例；表格关键数值单元格准确率不低于 97%，图表趋势判断准确率不低于 90%。
- 视觉证据区域定位命中率不低于 95%，且存在缺页、未解析区域或低置信结果时不得把文档标记为完整或输出确定事实。
- 同一评测配置重复运行结果可比较，报告包含代码、数据集、提示词、模型与索引版本。
- 中断恢复后已成功工具调用的重复执行次数为 0。
- 受控故障场景恢复成功率为 100%。
- 高风险工具未经批准执行次数为 0。
- 首轮 v7 迁移覆盖当前全部文档版本；迁移前后源 PDF 哈希变化数为 0，每个文档均有可复用、补充元数据、定向重提取或全量重提取的证据化决策。
- 新索引代际失败不得改变当前 active publication；发布后的索引、文档、事实、制品、声明、计算与报告必须属于同一发布快照且不存在悬空引用。
- v5.19 既有后端、前端和 OpenSpec 质量门禁不得回归。

## 范围

### 必选范围

- A：评测基线与发布门禁。
- B：金融可信内核。
- C0：通用可恢复执行基础，先服务多模态入库任务。
- M：可验证多模态财报理解。
- M 内的数据迁移：源 PDF 只读；复用合格 MinerU 产物；只对缺失或困难页定向重处理；为当前全部文档生成首个 v7 完整索引代际并重算无法证明兼容的 embedding。
- 关系型溯源：使用 SQLite 外键关系连接文档版本、制品、事实、声明、计算和报告，不引入图数据库。
- C1：可恢复研究任务产品化与交互。
- D：安全、审计与成本治理。
- E：研究任务与可审计报告交付。

### 延后范围

- MCP/A2A：待核心能力形成稳定 API 后以独立变更实施。
- 知识图谱：仅在至少 30 个经复核的多跳关系案例证明关系型方案无法达到批准门禁，且明确需要子公司、股东、供应链或风险传播图推理时，另立 OpenSpec 评估实体消歧、时态关系、图更新和查询收益。
- 团队多租户、ERP、数据库接入：不纳入 v7.0 首个可交付版本。
- 模型微调：在评测证明提示词、检索和事实层无法解决问题前不实施。

## 非目标

- 不整体迁移 LangGraph 或替换现有自研 Agent 框架。
- 不增加没有明确评测收益的新 Agent 角色。
- 不为了视觉效果改写已稳定页面。
- 不建设通用图片聊天、图片生成、音频或视频理解；多模态只覆盖金融 PDF 的表格、图表、扫描页、脚注和跨页结构。
- 不训练自有 OCR 或视觉基础模型；优先复用 MinerU 现有产物和已声明依赖，只在难例上调用类型化视觉能力。
- 不修改、覆盖或就地清洗源 PDF；页图、Markdown、表格、区域裁剪、索引和事实均属于可删除、可重建的版本化派生产物。
- 不以通用三元组或图数据库替代当前可由明确外键表达的审计关系。
- 不把 LLM 判断作为财务计算和质量门禁的唯一依据。
- 不宣称满足未经过正式审查的金融监管或合规标准。
- 不在未核查本地安装状态和未获得用户同意前安装新 Python 包。

## 交付策略

按 A → B → C0 → M → C1 → D → E 顺序推进。C0 只建立状态、检查点、幂等、租约和取消等通用基础，M 直接复用它执行 PDF/VLM/索引长任务；C1 再接入 Planner/Orchestrator、SSE 和研究任务 UI。每个工作包均独立执行 SDD、全红 TDD、实现、回归、代码审查和提交；前一门禁未通过，不进入下一包。A、B、C0、M、C1 为 v7.0 求职竞争力的最小闭环，D、E 为企业产品闭环。

## 主要风险

- LLM 裁判不稳定：以确定性评估器为主，LLM 裁判只覆盖语义维度并记录模型与提示词版本。
- 黄金答案错误：采用编制与复核两阶段分离流程，并保留来源页码和摘录；单人项目不得伪称双人审核。
- 结构化事实抽取误差：原始值与归一值同时保留，不覆盖来源文本。
- 多模态成本与误识别：先清点 MinerU 既有图片/表格，使用确定性页路由、内容哈希缓存和低置信拒绝，只让视觉模型处理图表、扫描页和复杂表格难例。
- 视觉定位失真：近似文本页码不得冒充 bbox；无法建立可靠页码或区域映射时标记 unresolved。
- 视觉提示词注入：图片与 OCR 文本始终作为不可信文档数据，不能改变系统指令、工具权限或审批状态。
- 任务恢复产生重复副作用：所有可恢复工具必须先定义幂等键和副作用等级。
- 并发控制命令覆盖状态：暂停、恢复、取消和审批使用 revision/CAS；超时或取消后的晚到结果不得复活旧步骤。
- 文档覆盖与索引竞态：同名新文件建立新内容版本，只有制品和索引完整后才激活；删除、重建和查询通过文档版本与索引代际固定语义协调。
- 旧向量不可证明兼容：当前索引缺少完整 parser/splitter/preprocess/embedding/schema 版本证据；首轮 v7 侧向重建全部 embedding，旧索引只作为回滚与基线，不直接导入新代际。
- 源文件与派生产物混淆：源 PDF 以内容哈希校验且只读，所有修复和增强输出写入独立版本目录，禁止反写原文件。
- 本地依赖不可复现：不得以“当前 Python 能导入”为已声明依赖证据，必须同时核对包元数据、`requirements.txt` 和 `requirements.lock`。
- 范围过大：每个工作包设置退出门禁；多模态严格限定金融 PDF，互操作、知识图谱和通用媒体理解明确延后。
- 版本语义冲突：路线版本使用 v7.0，Git 发布标签在最终发布时统一处理。

## 外部依据

- LangChain State of Agent Engineering：生产 Agent 的评测、追踪与可观测性已成为基础能力。
- Anthropic Agent Evals：Agent 评测需要覆盖多轮、工具调用、状态和执行环境，而非只看最终答案。
- OpenAI Agents SDK：快照、状态恢复和可持久化执行是长任务 Agent 的重要方向。

## 批准门禁

本提案批准后，先实施工作包 A。未获得批准前只允许完善规格和测试设计，不修改业务实现。
