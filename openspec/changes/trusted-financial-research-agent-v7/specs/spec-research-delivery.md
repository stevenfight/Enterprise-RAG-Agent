# 规格 E：研究工作流与可审计报告

## 要求：研究计划协作

### 场景：创建研究任务

- **当** 用户提交研究目标和范围
- **则** 系统生成可查看的计划、数据范围、预计成本和风险点

### 场景：调整计划

- **当** 用户在执行前修改范围
- **则** 重新计算受影响步骤和预算
- **且** 不修改无关步骤

## 要求：冲突审核

### 场景：存在待确认冲突

- **当** 报告依赖尚未裁决的关键金融事实
- **则** 报告进入待审核状态
- **且** 用户可以查看双方来源并批准、驳回或保持未决

## 要求：声明级报告

### 场景：生成报告

- **当** 研究任务达到报告生成条件
- **则** 每个关键声明关联事实、计算、来源或明确的分析判断标签
- **且** 报告记录生成版本、数据版本和时间

### 场景：人工创建待审核报告

- **当** 已登录且具有 `researcher` 角色的用户基于已持久化研究计划提交声明输入
- **则** 服务端生成只追加的待审核报告版本，并由服务端确定报告 ID、版本和审核状态
- **且** 未登录用户和不具有 `researcher` 角色的用户必须被拒绝
- **且** 本端点的角色门禁不替代研究任务执行链路的报告生成条件；任务是否必须处于 `completed` 状态仍需独立产品决策

### 场景：来源变化

- **当** 某事实被修订或失效
- **则** 只使依赖该事实的声明进入待复核
- **且** 其他已验证声明保持有效

## 要求：渐进导出

### 场景：首版导出

- **当** 用户导出首版报告
- **则** 先保证 Markdown/HTML 内容和证据完整

### 场景：文档格式扩展

- **当** 后续增加 PDF、Word 或 Excel
- **则** 每种格式均有独立布局与证据完整性验收
- **且** 不因格式转换丢失声明 ID 和来源关系

## 要求：复用现有界面

### 场景：新增任务工作台

- **当** 实现研究任务页
- **则** 复用现有布局、主题、DAG、证据面板和图表组件
- **且** 不重写已稳定聊天功能

## 要求：遗留运行任务处置与原子完成

### 场景：处置没有有效执行租约的遗留运行任务

- **当** 审批人对没有有效步骤租约、检查点或调用记录的 `running` 研究任务执行处置
- **则** 系统必须以当前 revision 和唯一 command_id 将原任务迁移为 `failed`
- **且** 追加可审计失败原因，禁止静默删除、重置或伪造报告
- **且** 非审批人、过期 revision、仍持有有效租约或已有检查点的任务必须被拒绝

### 场景：从已处置历史任务创建重试

- **当** 审批人对已失败且具有持久化计划的历史任务请求重试
- **则** 系统保留原任务及其失败审计，创建新的 `-retry-N` pending 任务并复制原计划快照
- **且** 新任务重新进入 submitted 审批流程，不得自动执行、回迁原运行或伪造报告
- **且** 重复 command_id 必须返回同一个新任务，缺计划、非 failed 或过期 revision 必须被拒绝

### 场景：最终报告步骤完成

- **当** 执行器持有最终步骤的有效租约并生成可追溯报告
- **则** 报告写入、最终步骤检查点、调用记录、租约释放和运行状态 `completed` 必须在同一 SQLite 事务提交
- **且** 任一写入失败时不得遗留报告、最终步骤检查点或 `completed` 状态

### 场景：研究步骤的租约生命周期

- **当** 执行器开始一个需要外部检索或模型计算的研究步骤
- **则** 必须先取得该步骤的有效租约，计算期间按 TTL 续租，且只有当前 owner 可以提交步骤结果
- **且** 其他工作者已持有有效租约时不得调用外部查询，也不得把租约竞争记为任务业务失败
- **且** 当前 owner 在未提交结果前异常退出或续租失败时，必须释放当前尝试并追加 `step_abandoned` 审计事件

### 场景：研究步骤绑定 Agent 与工具

- **当** 研究计划进入可执行状态
- **则** 每个计划步骤必须显式绑定已注册的 Agent 及其允许使用的工具
- **且** 绑定引用必须通过 `AgentRegistry` 校验，未知 Agent 或未授权工具不得执行
- **且** 每次步骤执行必须持久化 Agent、工具、状态和脱敏结果摘要，供任务详情只读展示
- **且** 轨迹不得写入 API 密钥、完整提示词或未经脱敏的外部响应正文

### 场景：绑定检索工具的实际调用

- **当** 可执行研究计划的 `retrieve` 步骤绑定了 `retrieve` 工具
- **则** 执行器必须经注入的现有 `ToolRegistry` 调用该工具，而不是额外调用通用查询函数
- **且** 绑定 `DataAgent` 时，Worker 查询上下文必须同时包含计划 `objective` 与已审批的完整 `scope`
- **且** 调用账本仅保存工具名称、成功状态与来源数量等脱敏摘要，不保存工具参数、来源正文或密钥
- **且** 工具未装配、调用失败或未返回可审计来源时，任务必须失败且不得生成报告
- **且** 没有绑定的历史计划仍保持既有通用查询路径

### 场景：绑定 VerifyAgent 审核检索声明

- **当** 可执行研究计划的 `review` 步骤绑定 `VerifyAgent + [verify]`，且本次 `retrieve` 已返回来源与声明
- **则** 审核 Worker 必须使用本次检索的完整来源正文和执行器提供的声明
- **且** 来源回答摘要可以继续按既有长度返回，但不得将截断摘要作为唯一审核正文
- **且** Worker 的 `verify` action input 不得替换或扩写执行器提供的声明、来源正文
- **且** 审核失败、无结论或未实际调用 `verify` 时任务必须失败，C0 只保存有效性、置信度和计数等脱敏摘要
