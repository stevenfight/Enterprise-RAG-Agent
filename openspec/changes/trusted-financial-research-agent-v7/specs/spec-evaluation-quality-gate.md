# 规格 A：金融 Agent 评测与质量门禁

## 要求：版本化黄金数据集

系统必须使用可校验、可评审和可版本化的数据集，不得仅以临时问题列表作为发布依据。

### 场景：加载有效样本

- **当** 评测运行器加载一个符合 schema 且已复核的样本
- **则** 样本进入对应评测集
- **且** 报告记录样本 ID、数据集版本和复核状态

### 场景：拒绝错误样本

- **当** 样本缺少期望事实、来源、页码、预期行为或版本信息
- **则** schema 校验失败
- **且** 不运行可能产生误导结果的评测

## 要求：分层评估

系统必须优先使用确定性评估器，并将 LLM 裁判结果与确定性结果分开记录。

### 场景：数字允许误差

- **当** 预测值和标准值只存在样本允许范围内的舍入差异
- **则** 数值评估通过
- **且** 报告保留原始值、归一值和误差

### 场景：高风险关键错误

- **当** 高风险样本的关键数值、单位、期间或拒答行为错误
- **则** 发布门禁直接失败
- **且** 平均分不得掩盖该错误

### 场景：LLM 裁判不可用

- **当** 无密钥 CI 不能运行 LLM 裁判
- **则** 仍完成 schema 与确定性核心评测
- **且** 报告明确语义评测未运行，不能记为通过

## 要求：基线差异

### 场景：比较候选版本

- **当** 候选结果与批准基线比较
- **则** 报告列出新增失败、已修复失败、分数变化和性能变化
- **且** 记录代码 SHA、模型、提示词、索引和数据集版本

## 要求：CI 分层门禁

### 场景：PR 核心评测

- **当** 创建目标为 main 的 PR
- **则** Quality Gate 使用受版本控制的回答、来源和工具轨迹夹具运行无密钥核心集
- **且** 不调用真实 DashScope、LangSmith 或 OpenEvals 在线服务
- **且** 报告明确该结果验证评测器与门禁，不冒充在线模型质量结果

### 场景：发布全量评测

- **当** 准备受控发布
- **则** 运行完整金融评测集和批准的语义评测
- **且** 未达到阈值不得标记发布就绪

### 场景：分阶段证据指标

- **当** A 阶段尚未提供结构化声明和 EvidenceBundle
- **则** 只记录答案级来源、页码与预期事实基线
- **且** 不将其命名为声明级证据支持率

- **当** B 阶段形成结构化声明
- **则** 再启用声明级证据支持率硬门禁

## 要求：样本治理

### 场景：用户纠错进入评测集

- **当** 收到真实失败或用户纠错
- **则** 先创建候选样本并完成人工来源复核
- **且** 未复核样本不得进入发布门禁
