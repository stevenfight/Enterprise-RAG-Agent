# 规格 B：金融可信内核

## 要求：共享版本化持久化

B、M、C、D 的元数据必须通过同一 V7MetadataStore 和统一迁移器持久化，各领域使用独立仓储接口，不得各建 SQLite/JSON 真值。

### 场景：迁移失败

- **当** schema migration 中途失败
- **则** 当前迁移事务回滚并保留启动前备份
- **且** 不修改旧 PDF、旧索引或 AgentMemory

### 场景：未知高版本

- **当** 数据库 schema 版本高于当前代码支持范围
- **则** 拒绝启动 v7 写路径并报告版本不兼容
- **且** 不自动降级、删库或重建

## 要求：统一金融事实

### 场景：保存事实

- **当** 系统从年报或人工核验结果创建金融事实
- **则** 同时保存原始值、原始单位、归一值、币种、期间、口径、来源、页码和摘录
- **且** 归一化不得覆盖原始数据

### 场景：事实修订

- **当** 已发布事实需要修订
- **则** 创建新版本并关联被替代事实
- **且** 历史报告仍能解析其原事实版本

## 要求：单位、币种、期间与口径归一

### 场景：可安全转换

- **当** 两个事实只有万元、亿元等确定性单位差异
- **则** 使用确定性规则转换后比较
- **且** 记录转换因子与过程

### 场景：汇率缺失

- **当** 两个事实币种不同且未提供适用日期与汇率来源
- **则** 不执行猜测性换算
- **且** 返回币种不可直接比较

### 场景：口径不一致

- **当** 两个事实属于集团与母公司等不同口径
- **则** 标记口径差异
- **且** 不将其判定为真实数值冲突

## 要求：确定性计算

### 场景：计算派生指标

- **当** 系统计算同比、CAGR、利润率或其他批准公式
- **则** 输入必须关联事实 ID
- **且** 输出包含公式、输入值、单位、精度和计算版本

### 场景：输入不兼容

- **当** 计算输入期间、币种、单位或口径不可兼容
- **则** 计算失败并说明原因
- **且** 不向 LLM 返回伪造结果

## 要求：冲突检测与裁决

### 场景：可解释差异

- **当** 差异由单位、舍入、期间或口径导致
- **则** 返回差异类型和归一后的比较结果

### 场景：真实冲突

- **当** 同指标、同期间、同口径事实归一后仍超过容差
- **则** 创建冲突记录并按来源权威度提出建议
- **且** 保留双方证据

### 场景：无法裁决

- **当** 证据不足以选择可信事实
- **则** 状态为需人工确认
- **且** 答案不得静默采用任一数值

## 要求：现有能力兼容

### 场景：旧三大运营商查询

- **当** 使用既有 `VerifiedFinancialFactRegistry` 公共方法查询 2024 年三大运营商营业收入
- **则** 返回值、顺序、来源和正文格式保持既有测试兼容

### 场景：回答级证据链

- **当** 新事实支撑回答声明
- **则** 现有证据链增加事实、计算和冲突关联
- **且** 未使用新字段的前端仍可展示原来源信息
