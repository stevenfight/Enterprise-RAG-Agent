# 规格 M：可验证多模态财报理解

## 要求：复用既有解析制品

系统必须优先清点并复用 MinerU 已生成的 Markdown、图片、表格和公式制品，不得默认重新解析所有页面。

### 场景：已有完整制品

- 给定 PDF 哈希、MinerU 版本和产物均未变化
- 当系统重建多模态索引
- 那么必须复用相同制品 ID 和缓存
- 并且不得重复调用视觉模型

### 场景：制品缺失或无法定位

- 给定 Markdown 引用了不存在的图片，或图片无法可靠关联页码/bbox
- 当系统建立制品清单
- 那么必须把相应制品标记为 missing 或 unresolved
- 并且不得猜测页码、区域或把文档标记为完整

## 要求：文档身份与版本

系统必须区分逻辑文档和内容版本，禁止同名上传直接覆盖仍被事实、索引或在途请求引用的原文件。

### 场景：重复内容上传

- 给定相同内容哈希再次上传
- 当系统校验完成
- 那么幂等返回既有 document_version_id
- 并且不得重复解析、调用视觉模型或构建索引

### 场景：同名新内容

- 给定文件名相同但内容哈希不同
- 当上传新版本
- 那么旧 active 版本继续服务，新版本进入 processing
- 并且只有新版本完整通过制品与索引门禁后才能激活

## 要求：文档完整性清单

每份文档必须有 `DocumentAssetManifest`，记录页数、解析批次、成功/失败页段、制品、解析器版本和完整性状态。

清单必须有 schema 版本和明确状态迁移，原子保存；文件存在本身不得替代清单成功状态。

### 场景：MinerU 分批解析部分失败

- 给定大 PDF 中一个页批次解析失败，其余批次成功
- 当系统完成入库
- 那么文档状态必须为 incomplete，并列出缺失页段
- 并且检索或回答不得宣称全文已完整索引

### 场景：文档完整

- 给定所有 PDF 页面均有可核对的解析状态
- 当清单校验通过
- 那么系统才可标记 complete

## 要求：页图与坐标

系统必须使用现有 PyMuPDF 能力生成幂等页图和统一坐标空间，并区分文本近似页码与视觉精确区域。

### 场景：生成页面制品

- 给定相同文档哈希、页码和渲染版本
- 当重复请求页图
- 那么必须返回相同 artifact ID，并复用缓存

### 场景：旋转或裁剪页面

- 给定带旋转或非标准页面框的 PDF
- 当定位视觉区域
- 那么 API bbox 与前端高亮必须映射到同一规范化坐标

## 要求：页面按需路由

系统必须通过可解释信号把页面分类为 text、table、chart、scan 或 mixed；纯文本页继续走原 RAG，仅难例调用视觉能力。

### 场景：普通文本页

- 给定有可用文本层且无复杂视觉结构的页面
- 当页面进入处理链
- 那么不得调用视觉模型
- 并且原文本检索结果保持兼容

### 场景：视觉能力不可用

- 给定页面确需视觉模型但 provider 未配置或调用失败
- 当系统处理页面
- 那么必须返回 unavailable/incomplete
- 并且不得静默退回文本猜测结构或数值

## 要求：结构化表格理解

系统必须优先使用 MinerU HTML/Markdown 表格，保留多级表头、合并单元格、空值、单位、期间、脚注和原始文本；只有复杂或损坏结构才调用视觉模型。

### 场景：已有可用 HTML 表格

- 给定包含 row/colspan 的 MinerU 表格
- 当系统提取结构化单元格
- 那么必须保留跨行跨列关系和原始值
- 并且不得从 `preprocess_table_text()` 的扁平文本反推表格真值

### 场景：跨页续表

- 给定相邻两页有相同标题、兼容表头与列结构
- 当续表规则全部满足
- 那么可建立 continuation 关系并保留原页区域
- 但任一关键条件不满足时不得自动合并

## 要求：图表理解

系统必须结构化提取标题、图例、轴、单位、期间、系列、数据点和趋势，并保留图表区域证据。

### 场景：只可判断趋势

- 给定图表分辨率不足以可靠读取精确数值
- 当模型能判断方向但不能读数
- 那么系统只能输出带置信度的趋势候选
- 并且不得生成精确数值事实

### 场景：图表与正文冲突

- 给定图表与正文对同一指标、期间和口径给出不一致结果
- 当完成归一化
- 那么必须进入统一冲突引擎
- 并且不得因来源模态不同而静默选择一方

## 要求：扫描页与低置信处理

只有页面无可用文本层或现有解析质量不足时才能进入扫描识别；结果必须保留区域、方法和置信度。

### 场景：低置信财务数字

- 给定扫描区域中的关键数字低于批准置信门槛
- 当系统构建事实
- 那么只能保存为 candidate/pending_review
- 并且不得进入 verified 事实或确定性计算

## 要求：统一金融事实与证据

文本、表格和图表结果必须使用 B 阶段同一归一器、来源权威度、FinancialFact、冲突模型和 EvidenceBundle。

### 场景：视觉数值进入事实层

- 给定表格单元格包含数值、单位、期间和口径
- 当抽取质量达到批准门槛
- 那么事实必须关联 document、page、bbox、artifact、原始值与提取方法
- 并且 SourceInfo 通过可选字段保持旧 API 兼容

## 要求：视觉内容安全

图片、OCR 文本、图例和脚注必须始终作为不可信文档数据，不得改变系统指令、权限、预算或审批。

### 场景：图片内提示词注入

- 给定图像文字要求忽略规则或调用未授权工具
- 当视觉模型返回内容
- 那么结构化解析器必须丢弃该指令语义
- 并且工具策略和审批状态保持不变

### 场景：资源异常

- 给定超大页图、异常像素或超出预算的文档
- 当进入渲染或视觉调用
- 那么系统必须在资源边界停止并留下可审计错误

## 要求：完整生命周期

视觉制品、事实和索引必须服从原知识库上传、删除与重建生命周期。

### 场景：删除 PDF

- 给定文档已产生 Markdown、页图、区域图、清单、视觉事实和索引
- 当用户通过既有删除入口删除文档
- 那么必须先停止该版本对新查询可见，再幂等清理所有派生数据
- 并且不得留下可被检索的孤儿事实

## 要求：现有证据界面兼容扩展

前端必须在现有 EvidencePanel、SourceCard 和 EvidenceChainGraph 中展示页面预览、区域高亮、证据类型和完整性警告。

### 场景：旧文本来源

- 给定 SourceInfo 不含任何多模态字段
- 当旧回答在新版前端展示
- 那么行为和视觉必须保持兼容

### 场景：视觉来源

- 给定来源包含 page_image_url、bbox 和 artifact_id
- 当用户打开证据
- 那么系统必须显示对应页图并高亮区域
- 并且 unresolved 或 incomplete 状态必须显式可见

### 场景：读取页图

- 给定已认证用户提交合法 artifact ID
- 当服务端从 manifest 验证其文档和真实路径
- 那么返回对应图像和缓存标识
- 但提交本地路径、未知 artifact ID 或跨文档引用时必须拒绝

## 要求：视觉索引失败显式化

视觉结构摘要必须进入现有 FAISS/BM25 索引；视觉路径中的 embedding 失败不得以零向量占位后标记成功。

### 场景：视觉 embedding 批次失败

- 给定视觉结构摘要调用 embedding 失败
- 当使用索引 strict 模式
- 那么本次视觉索引步骤必须失败并使 manifest 保持 incomplete
- 并且不得写入可被检索的零向量视觉制品

## 要求：索引代际激活

索引必须在不可见 staging generation 中完整构建和验证，再由 PublicationSet 与文档、制品和事实可见性一起原子发布；请求开始时固定 publication。

### 场景：构建中断

- 给定新 generation 部分文件已经写入但校验未完成
- 当构建失败或进程中断
- 那么 active publication 保持不变
- 并且 staging 文件不得被 Retriever 加载

### 场景：并发查询与激活

- 给定查询已固定旧 publication，随后含新 generation 的 publication 激活
- 当查询继续执行
- 那么该查询的索引、文档、制品和事实始终使用旧 publication，新请求使用新 publication
- 并且 RAGGenerator、RetrieveTool、CompareTool 的新请求看到同一 active publication

### 场景：删除与查询竞态

- 给定文档版本进入 deleting
- 当新查询创建检索快照
- 那么必须排除该版本
- 并且删除完成后 artifact API 与新查询均不可访问其派生数据
