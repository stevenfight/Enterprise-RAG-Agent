# 设计：Agent SSE 流式接口鉴权旁路修复

## 根因

鉴权中间件以精确路径白名单在会话和 Bearer 校验之前直接放行 `/api/agent/stream`。原注释将 EventSource 无法携带自定义请求头作为放行理由，但项目已经在同一中间件中提供服务端 `research_session` 校验；因此静态放行既不必要，也扩大了未认证访问面。

## 最小修复

从 `APIAuthMiddleware.SKIP_PATHS` 移除 `/api/agent/stream`。请求随后沿用既有顺序：

1. 白名单路径和前缀继续直接放行。
2. 有效的服务端研究会话继续放行，兼容 EventSource 的 HttpOnly Cookie 身份。
3. 其余请求必须携带正确 Bearer API Key；缺失或错误时立即 401。
4. 通过鉴权的请求才进入原有 SSE 路由，事件生成和业务错误处理不变。

## 验证边界

测试直接驱动中间件并用无副作用下游 ASGI 应用记录是否被调用。这样可以证明认证拒绝发生在路由前，且正确 API Key 和有效研究会话仍能透传，不需要启动 Agent、访问 SQLite、调用 Provider 或使用真实凭据。

## 兼容性决策

v5.19 对该接口的无 Key/错误 Key 行为为 503；该行为是已确认的安全缺陷，候选分支故意改为 401。兼容性清单必须保留历史指纹并明确记录这是安全修复例外，不能再声称候选与 v5.19 的该项行为一致。
