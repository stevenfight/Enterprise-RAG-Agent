## 一、项目概览

本项目是一个基于 RAG（检索增强生成）技术的企业年报智能问答系统，支持对 12 份 PDF 财报的自然语言问答。当前覆盖 4 家公司：中芯国际、中国移动、中国联通、中国电信。

### 核心能力

| 能力 | 说明 |
|------|------|
| PDF 解析 | MinerU API 将 PDF 转为 Markdown |
| 文本分块 | Small-to-Big 策略：子块 150 tokens (Embedding)，父块 500 tokens (LLM 上下文) |
| 混合检索 | BM25 关键词 + 向量语义检索，意图驱动动态权重 |
| 重排 | gte-rerank-v2 批量评分 |
| 意图识别 | 6 类意图分类 + 域外问题拦截 + 查询改写 |
| 多轮对话 | 支持 5 轮对话上下文 |
| 双界面 | Streamlit Web + FastAPI REST API |

### 端到端流程

```
用户查询
  -> QueryProcessor (意图识别 + 查询改写 + 域外拦截)
  -> HybridRetriever (混合检索: BM25 + 向量 + gte-rerank-v2 重排)
  -> RAGGenerator (意图专用 Prompt + qwen-max 生成 + 对话记忆)
  -> 最终答案 + 来源信息 + 置信度
```

### 3.4 配置 API Key

项目需要两个 API Key：

| Key | 用途 | 获取地址 |
|-----|------|---------|
| DASHSCOPE_API_KEY | Embedding / 重排 / LLM 生成 | [阿里云 DashScope 控制台](https://dashscope.console.aliyun.com/) |
| MINERU_API_KEY | PDF 解析 | [MinerU 官网](https://mineru.net/) |

**方式一：系统环境变量（推荐）**

```powershell
[System.Environment]::SetEnvironmentVariable("DASHSCOPE_API_KEY", "your_key", "User")
[System.Environment]::SetEnvironmentVariable("MINERU_API_KEY", "your_key", "User")
```

**方式二：.env 文件**

在项目根目录创建 `.env` 文件：

```
DASHSCOPE_API_KEY=your_key_here
MINERU_API_KEY=your_key_here
```

API Key 读取优先级：`os.getenv` -> `Windows 注册表` -> `.env 文件`（见 `src/utils.py` 的 `get_api_key` 实现）。

## 七、关键设计决策

### 7.1 Small-to-Big 检索策略

- **子块 (150 tokens)**：用于 Embedding 向量检索，粒度细，匹配更精准
- **父块 (500 tokens)**：返回给 LLM 做上下文，包含更完整的语义信息
- 检索时用子块匹配，返回对应父块的完整文本

### 7.2 混合检索权重自适应

根据查询意图动态调整 BM25 和向量检索的权重：

| 意图 | BM25 权重 | 向量权重 | 原因 |
|------|----------|---------|------|
| financial_data | 0.6 | 0.4 | 精确关键词（营收、利润）更重要 |
| comparison | 0.5 | 0.5 | 关键词和语义同等重要 |
| business_analysis | 0.4 | 0.6 | 语义理解更重要 |
| trend | 0.3 | 0.7 | 趋势分析需要更深层语义 |
| general | 0.5 | 0.5 | 默认均衡 |

### 7.3 意图识别与查询改写流程

```
用户查询
  -> 获取对话上下文 (conversation_manager.get_context_string(max_turns=3))
  -> LLM (qwen-plus) 思维链推理，传入 conversation_context
  -> 输出：intent / confidence / mentioned_companies / rewritten_query
  -> 域外问题 (out_of_domain) -> 直接返回默认回复，跳过检索
  -> 低置信度 (< 0.4) -> 提示用户补充信息
  -> 正常意图 -> 选择对应专用 Prompt + 动态权重
  -> 对比查询 (comparison) -> 使用原始查询检索（保留完整公司列表）
  -> 非对比查询 -> 使用改写查询检索
```

**查询改写支持对话上下文（第三轮新增）**：

当用户进行多轮对话时，查询改写会结合历史对话补全指代信息：

```
第1轮 - 用户: 中国移动2024年营收是多少？
第1轮 - 助手: 中国移动2024年营业收入为10,408亿元...

当前查询: 那联通呢？
改写后: 中国联通2024年营收
```

实现方式：`query_processor.process(query, conversation_context=...)` 将对话历史传入 `_rewrite_query()`，通过 `REWRITE_PROMPT_TEMPLATE` 的 `{context_section}` 占位符注入历史信息。

### 7.4 指令细分化 Prompt

根据意图不同，选择不同的系统提示词：

- **financial_data**：CPA 财务分析师角色，要求精确数值，禁止模糊表述
- **trend**：趋势分析专家，关注时间序列数据，禁止推测未来
- **business_analysis**：业务分析师，关注竞争优势和业务板块
- **comparison**：对比分析专家，要求结构化表格输出

### 8.2 常见问题排查

| 问题 | 可能原因 | 排查方向 |
|------|---------|---------|
| `Embedding API 调用失败` | API Key 未配置或无效 | 检查 `DASHSCOPE_API_KEY`，运行 `python -c "from src.utils import get_api_key; print(get_api_key())"` |
| `FAISS 索引文件不存在` | 未构建索引或路径错误 | 运行 `python src/ingestion.py --status` 查看状态 |
| `EMBEDDING_DIM mismatch` | Embedding 模型不匹配 | 确认使用的是 `text-embedding-v3` (1024维) |
| 查询结果不相关 | 检索权重不匹配 | 检查意图识别结果，确认权重是否正确 |
| 中文编码乱码 | 控制台编码问题 | 所有文件使用 UTF-8 编码，PowerShell 执行 `chcp 65001` |
| API 请求超时 | 网络问题或配额不足 | 超时参数：LLM 60s / Embedding 30s / gte-rerank-v2 15s |
| 对比查询缺某家公司数据 | 候选截断或营收数据未进入重排 | 检查日志中的 `comparison_candidates_limit` 和 `_ensure_numeric_data_coverage` 日志 |
| 多轮对话指代未补全 | 对话上下文未传入查询改写 | 检查 `conversation_context` 是否正确传入 `process()` |

## 十二、Agent 模式开发指南 (NEW)

### 12.1 Agent 架构概览

```
用户查询 -> TaskPlanner(拆解子任务) -> ReActAgent(循环推理)
  -> ToolRegistry(工具调用) -> AgentMemory(记忆管理)
  -> AnswerReflector(反思修正) -> 最终答案
```

### 12.2 核心模块

| 模块 | 文件 | 功能 |
|------|------|------|
| Agent 核心 | `src/agent_core.py` | ReAct 循环 (Thought/Action/Observation) |
| 三层记忆 | `src/agent_memory.py` | 工作记忆/情景记忆/长期记忆 |
| 查询规划 | `src/planner.py` | 4种拆解策略 + DAG 拓扑排序 |
| 答案反思 | `src/reflector.py` | 幻觉检测 + 来源完整性 + 自动修正 |
| 工具集 | `src/tools/` | 检索/计算/对比/图表/验证 5 个工具 |
