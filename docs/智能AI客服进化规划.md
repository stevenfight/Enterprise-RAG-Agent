# 智能AI客服进化整体规划

> 从"企业级财务年报分析智能RAG-Agent"进化为"企业级智能AI客服系统"

**版本**: v1.0  
**日期**: 2026-08-02  
**当前项目形态**: 垂直领域（财务年报）智能问答Agent  
**目标项目形态**: 通用企业级智能AI客服系统

---

## 一、核心差异分析

| 维度 | 当前（智能问答Agent） | 目标（智能AI客服） |
|------|----------------------|---------------------|
| **定位** | 单领域知识问答工具 | 企业级全场景客服平台 |
| **对话模式** | 单轮/短多轮 Q&A | 长多轮对话、上下文贯穿 |
| **用户类型** | 内部分析人员（单一角色） | 多角色外部客户（不同权限） |
| **知识范围** | 财务年报（单一知识库） | 多知识库（产品、FAQ、政策等） |
| **交互目标** | 回答问题 | 解决问题、引导、转化、安抚 |
| **并发要求** | 低并发 | 高并发、多会话并行 |
| **运营需求** | 无 | 工单、质检、数据看板、人工介入 |
| **渠道** | Web界面 | Web、API、企微、公众号等多渠道 |

## 三、阶段一：基础客服能力建设

### 3.1 多轮对话会话管理

**现状**: 当前 `src/conversation.py` 提供基础对话历史管理，`src/agent_memory.py` 有三层记忆（短期/工作/长期），但偏向单次分析任务。

**改造方向**:
- **会话生命周期管理**: 创建会话 → 活跃 → 等待 → 超时关闭 → 归档
- **会话上下文窗口**: 支持滑窗 + 摘要压缩，保证长对话不丢上下文
- **会话持久化**: 当前仅内存存储，需增加数据库持久化（SQLite → PostgreSQL）
- **断点续聊**: 客户离开后回来能继续之前的对话

**涉及文件**:
- `src/conversation.py` - 增强为会话管理器
- `src/agent_memory.py` - 扩展记忆层支持客服场景
- 新增 `src/session_manager.py` - 会话生命周期管理

### 3.2 客服场景专用记忆

**新增能力**:
- **客户画像记忆**: 记录客户身份、偏好、历史问题类型
- **问题追踪记忆**: 记录当前会话中未解决的问题链路
- **跨会话记忆**: 同一客户多次咨询的关联（如"上次您提到的问题..."）

### 3.3 欢迎语与基础分流

**新增能力**:
- **场景化欢迎语**: 根据入口渠道、客户类型生成不同欢迎语
- **基础分流**: "请问您想咨询哪方面的问题？产品、订单、售后、财务..."
- **非工作时间提示**: 检测时间，提示人工坐席在线时间

## 四、阶段二：智能路由与意图理解

### 4.1 客服意图分类体系

**现状**: `src/query_processor.py` 目前有针对财务问题的意图识别（如数据查询、对比分析、趋势分析等）。

**改造方向**: 扩展为客服通用意图分类：

```
一级意图          二级意图
─────────────────────────────
产品咨询    →    产品功能、价格、对比、适用场景
订单查询    →    订单状态、物流、修改、取消
售后服务    →    退换货、保修、维修进度、投诉
账户问题    →    注册登录、密码找回、实名认证、权限
财务相关    →    年报分析、财报查询、指标解读（现有能力）
人工服务    →    转人工、投诉升级、紧急问题
闲聊其他    →    问候、感谢、无关问题
```

**涉及文件**:
- `src/query_processor.py` - 扩展意图识别模型
- 新增 `src/intent_classifier.py` - 客服意图分类器

### 4.2 FAQ快速匹配

**新增能力**:
- **FAQ知识库**: 高频问题向量化存储，直接匹配返回标准答案
- **语义匹配**: 客户问法变化时仍能匹配到对应FAQ
- **FAQ优先级**: FAQ命中时跳过复杂RAG，直接返回，降低延迟
- **FAQ管理后台**: 支持运营人员增删改FAQ

**涉及文件**:
- 新增 `src/faq_matcher.py` - FAQ匹配引擎
- 新增 `src/faq_manager.py` - FAQ知识库管理

### 4.3 多知识库路由

**现状**: 当前仅接入财务年报单一知识库。

**改造方向**:
- **知识库注册中心**: 管理多个知识库（产品文档、FAQ、政策文件、操作手册等）
- **按意图路由**: 产品咨询 → 产品知识库；售后 → 售后知识库
- **知识库优先级**: 同一问题可能跨知识库，按优先级融合结果

**涉及文件**:
- `src/retrieval.py` - 扩展支持多知识库检索
- 新增 `src/knowledge_registry.py` - 知识库注册与管理

### 4.4 客户情绪检测

**新增能力**:
- **负面情绪识别**: 检测客户愤怒、焦虑、失望情绪
- **情绪升级策略**: 负面情绪持续 → 主动建议转人工
- **安抚话术注入**: 在回复中自动加入安抚语句
- **情绪标签记录**: 用于后续质检和分析

**涉及文件**:
- 新增 `src/sentiment_analyzer.py` - 情绪分析器

## 五、阶段三：多渠道接入

### 5.1 企业微信接入

**现状**: `src/api_service.py` 已有 `/api/langbot/chat` 接口，兼容 LangBot 企微格式。

**改造方向**:
- **企微原生接入**: 直接对接企业微信开放平台（消息推送 + 回调）
- **企微应用**: 作为企微内部应用嵌入
- **企微客服**: 接入企微"微信客服"功能

**涉及文件**:
- 新增 `src/channels/wecom_channel.py` - 企微渠道适配器

### 5.2 微信公众号接入

**新增能力**:
- 公众号消息接收与回复（被动回复 + 客服消息）
- 菜单配置（智能客服入口）
- 图文消息推送

**涉及文件**:
- 新增 `src/channels/wechat_mp_channel.py` - 公众号渠道适配器

### 5.3 通用API渠道

**新增能力**:
- **Web Widget SDK**: 可嵌入任意网页的客服浮窗（类似 Intercom）
- **开放API**: 供第三方系统调用
- **Webhook**: 事件推送（会话开始/结束、转人工等）

**涉及文件**:
- 新增 `src/channels/api_channel.py` - API渠道
- `frontend/` 新增 `widget/` - 嵌入式客服组件

### 5.4 渠道抽象层

**设计原则**: 所有渠道统一接入，内部统一处理。

```
渠道层（Channel Layer）
├── WeComChannel（企微）
├── WeChatMPChannel（公众号）
├── WebWidgetChannel（网页）
├── APIGatewayChannel（API）
└── StreamlitChannel（现有，内部测试）
        │
        ▼
消息统一层（Unified Message Bus）
        │
        ▼
客服核心引擎（Customer Service Engine）
```

**涉及文件**:
- 新增 `src/channels/__init__.py` - 渠道注册中心
- 新增 `src/channels/base_channel.py` - 渠道抽象基类
- 新增 `src/message_bus.py` - 统一消息总线

## 六、阶段四：运营体系搭建

### 6.1 工单系统

**新增能力**:
- **自动建单**: 转人工时 / 问题未解决时 / 客户主动要求时自动创建工单
- **工单状态流转**: 待处理 → 处理中 → 已解决 → 已关闭
- **工单分配**: 按技能组 / 负载自动分配给人
- **工单关联**: 关联原始对话记录

**涉及文件**:
- 新增 `src/ticket_system/` - 工单系统模块
  - `ticket_manager.py` - 工单管理器
  - `ticket_model.py` - 工单数据模型

### 6.2 人工坐席系统

**新增能力**:
- **坐席工作台**: 实时查看等待队列、在线会话、历史记录
- **转人工策略**: 关键词触发 / 情绪触发 / 置信度低触发 / 客户主动请求
- **坐席接管**: 坐席实时查看对话并可介入回复
- **坐席辅助**: AI为坐席推荐回复话术

**涉及文件**:
- 新增 `src/agent_desk/` - 坐席工作台后端
- `frontend/src/pages/` 新增 `AgentDesk/` - 坐席前端页面

### 6.3 质检体系

**新增能力**:
- **自动质检规则**: 关键词检测、响应时间、是否转人工成功
- **质检评分**: AI对会话质量打分
- **质检报表**: 按坐席 / 日期 / 维度统计
- **告警机制**: 差评会话自动告警

**涉及文件**:
- 新增 `src/quality_check/` - 质检模块

### 6.4 SLA管理

**新增能力**:
- **响应时间SLA**: 首次响应、平均响应时间
- **解决时间SLA**: 问题从创建到解决的时间限制
- **排队策略**: VIP客户优先、紧急问题优先
- **超时告警**: 接近/超过SLA时告警

**涉及文件**:
- 新增 `src/sla_manager.py` - SLA策略管理

## 八、阶段六：持续学习与优化

**新增能力**:

**新增能力**:
- **意图规则优化**: 基于误分类数据自动调整分类规则

## 十、技术选型建议

| 组件 | 当前方案 | 推荐进化方案 | 原因 |
|------|---------|-------------|------|
| 后端框架 | FastAPI | FastAPI（保持） | 成熟稳定，异步支持好 |
| 数据库 | SQLite/ChromaDB | PostgreSQL + pgvector | 支持并发、向量检索一体化 |
| 缓存 | 无 | Redis | 会话缓存、FAQ热数据缓存 |
| 消息队列 | 无 | Redis/RabbitMQ | 渠道消息削峰、异步通知 |
| 向量数据库 | ChromaDB | Milvus / pgvector | 多知识库、更大规模 |
| LLM | DashScope | DashScope + 本地微调模型 | 降低成本、提升专项能力 |
| 前端 | Streamlit + React | React（主）+ Streamlit（内部维护） | 更灵活可控 |
| 监控 | LangSmith | LangSmith + Prometheus + Grafana | 全链路监控 |
| 日志 | print/logging | ELK / Loki | 集中日志管理 |

## 十二、风险与注意事项

1. **数据安全**: 客服系统涉及客户隐私数据（联系方式、订单等），需要加密存储和脱敏处理
2. **幻觉控制**: 客服场景对回答准确性要求极高，需增加更强的幻觉检测机制
3. **渐进式迁移**: 建议保留原有财务问答能力，以"财务咨询"作为客服系统的一个子域
4. **人力配合**: 运营体系（工单、坐席、质检）需要业务人员配合才能落地
5. **合规性**: 若涉及海外客户，需注意GDPR等数据合规要求
6. **成本控制**: 多轮对话带来更多LLM调用，需做好Token预算和缓存策略

## 十三、建议的起步策略

推荐**MVP快速验证**路径（取阶段一+阶段二的子集）：

1. 先做一个**独立的知识库客服Demo**（不破坏现有财务分析功能）
2. 接入**一个真实业务知识库**（如产品FAQ）
3. 实现**基础多轮对话 + FAQ匹配 + 简单转人工**
4. 在一个**内部小渠道**（如Streamlit或企微内部群）试运行
5. 收集反馈后再逐步扩展
