# 企业文档接入开发指南

> **文档状态**: Agent 改造不影响数据管道，本文档完全适用
> 编码: UTF-8
> 更新轮次: 第二轮
> 适用场景: 向现有系统新增企业文档、更新已有文档、新增公司
> 当前状态: 4 家公司 (中芯国际、中国移动、中国联通、中国电信)，12 份 PDF

---

## 一、文档接入总览

新增或修改文档涉及以下 6 个步骤，按顺序执行：

```
Step 1: 放置 PDF         -> pdf_reports/ 目录
Step 2: PDF 解析          -> python src/pdf_mineru.py
Step 3: 文本分块          -> python src/text_splitter.py
Step 4: 构建/重建索引     -> python src/ingestion.py --company <公司名> --rebuild
Step 5: 验证              -> 启动服务，测试查询
Step 6: 自动化测试        -> python tests/test_document_integration.py
```

## 三、场景一：为一已有公司新增一份 PDF 文档

**场景描述**：中芯国际已经有 9 份研报，现在要新增一份新的研报 PDF。

### Step 1：放置 PDF 文件

将 PDF 放入 `pdf_reports/` 目录：

```bash
# 例如新增文件
cp 新研报.pdf pdf_reports/
```

### Step 2：解析 PDF

```bash
python src/pdf_mineru.py
```

这会扫描 `pdf_reports/` 下所有 PDF，通过 MinerU API 转为 Markdown，输出到：
`data/stock_data/debug_data/03_reports_markdown/`

**关键逻辑**（`src/pdf_mineru.py`）：
- 自动识别文件名中的公司名（中芯国际/中国电信/中国移动/中国联通等）
- 生成 `subset.csv` 元数据文件（包含 SHA1 和公司名映射）
- PDF 解析支持断点续传

### Step 3：文本分块

```bash
python src/text_splitter.py
```

这会读取 Markdown 文件和 `subset.csv`，进行 Small-to-Big 分块，输出到：
`data/stock_data/databases/chunked_reports/`

**分块参数**（`src/text_splitter.py`）：
- 父块：~500 tokens
- 子块：~150 tokens
- 分块策略：按段落边界切分，父块按子块聚合

### Step 4：重建该公司索引

```bash
# 必须使用 --rebuild，因为新增了文档
python src/ingestion.py --company 中芯国际 --rebuild
```

这会：
1. 删除 `vector_dbs/中芯国际/` 下的旧索引文件
2. 重新读取 `chunked_reports/` 下中芯国际的所有分块数据
3. 调用 Embedding API 生成向量
4. 构建 FAISS 索引 + BM25 索引
5. 更新 `company_registry.json` 中的记录

### Step 5：验证

```bash
# 启动 Streamlit 界面
streamlit run app_streamlit.py

# 或通过 API 测试
curl -X POST http://localhost:8000/api/query \
  -H "Content-Type: application/json" \
  -d '{"query": "中芯国际最新产能情况", "company_name": "中芯国际"}'
```

## 四、场景二：替换/更新一个已有 PDF 文档

**场景描述**：中国电信的 2024 年年报有了新版 PDF，需要替换旧的。

### 操作步骤

1. **替换 PDF**：用新版 PDF 覆盖 `pdf_reports/` 下的同名文件，或删除旧文件放入新文件

2. **重新解析**：
```bash
python src/pdf_mineru.py
```

3. **重新分块**：
```bash
python src/text_splitter.py
```

4. **重建索引**：
```bash
python src/ingestion.py --company 中国电信 --rebuild
```

5. **验证查询**

> **注意**：如果新旧 PDF 文件名一致，`text_splitter.py` 会通过 `subset.csv` 中的 SHA1 值自动识别变更并重新分块。

## 五、场景三：新增一家公司

**场景描述**：当前系统只有 4 家公司，需要新增比如"宁德时代"。

### Step 1：放置 PDF 文件

```bash
# 将宁德时代相关的 PDF 放入 pdf_reports/ 目录
```

确保文件名中包含公司名称关键词，系统会自动识别。

### Step 2：检查公司名识别规则

系统在 `src/pdf_mineru.py` 的 `_extract_company_name()` 函数中通过关键词和简称映射识别公司名：

```python
# 关键词列表：文件名包含这些词时自动匹配
company_keywords = [
    "中芯国际", "宁德时代", "比亚迪", "腾讯", "阿里巴巴",
    "贵州茅台", "中国平安", "招商银行", "美的集团",
    "中国电信", "中国移动", "中国联通",
]

# 简称映射：文件名含简称时自动映射
short_name_map = {
    "电信": "中国电信",
    "移动": "中国移动",
    "联通": "中国联通",
}
```

**如果新增公司不在现有映射中**：

1. 在 `company_keywords` 中添加新公司全称
2. 如有简称需求，在 `short_name_map` 中添加映射
3. 或者确保文件名中直接包含完整的公司名称

### Step 3：一次执行 3 个步骤

```bash
# 解析 PDF
python src/pdf_mineru.py

# 文本分块
python src/text_splitter.py

# 构建新公司索引（自动识别新公司）
python src/ingestion.py
```

如果只想构建新公司的索引（不重复处理已有公司）：

```bash
python src/ingestion.py --company 宁德时代
```

### Step 4：补充系统配置（可选但推荐）

#### 4.1 添加公司简称映射

在 `src/retrieval.py` 中更新 `COMPANY_ABBREV_MAP`：

```python
COMPANY_ABBREV_MAP = {
    "中芯国际": ["中芯"],
    "中国电信": ["电信"],
    "中国移动": ["移动"],
    "中国联通": ["联通"],
    "宁德时代": ["宁德", "CATL"],  # 新增
}
```

#### 4.2 补充 BM25 查询扩展词典

如果新公司所在行业有特殊术语，在 `config/bm25_expansions.json` 中添加：

```json
{
    "动力电池": ["动力电池", "锂电池", "电池装机量", "电池出货量"],
    "装机量": ["装机量", "电池装机量", "市场份额"]
}
```

#### 4.3 补充财经自定义词典

如果新行业有 jieba 无法正确分词的术语，在 `config/financial_dict.txt` 中添加（每行格式：`词 词频 词性`）：

```
动力电池 10 n
电池装机量 10 n
```

### Step 5：验证


## 六、场景四：增量追加文档（不重建已有索引）

**场景描述**：只想为新出现的 PDF 文档构建索引，不影响已有公司的索引。

### 当前系统行为

`python src/ingestion.py`（不带参数）的行为：
- 遍历 `chunked_reports/` 下所有已分块的公司
- **跳过** `company_registry.json` 中已存在的公司
- 只为**新出现的公司**构建索引

### 如果需要为已有公司追加新文档

系统当前不支持真正的增量追加（不改代码的情况下）。推荐方案：

```bash
# 方案：重建该公司索引（包含新旧所有文档）
python src/ingestion.py --company <公司名> --rebuild
```

**重建成本估算**（以中芯国际 4195 子块为例）：
- Embedding API 调用：约 420 批 (4195/10)，每批 ~0.5s 间隔
- 总耗时：约 3-5 分钟
- API 调用次数：约 420 次

## 八、BM25 与检索配置调优

### 8.1 查询扩展词典 (bm25_expansions.json)

当用户查询某个术语时，自动扩展为多个同义词进行检索。

**文件位置**：`config/bm25_expansions.json`

**格式说明**：
```json
{
    "标准术语": ["标准术语", "同义词1", "同义词2", "同义词3"]
}
```

**扩展示例**：当用户查询"营收"时，BM25 检索会自动扩展为 `"营收" + "营业收入" + "主营业务收入" + "营业总收入"` 的联合查询。

**添加新术语**：
1. 分析目标行业的常用术语和缩写
2. 确定标准术语作为 key
3. 列出所有可能的同义表达作为 values
4. 追加到 JSON 文件末尾

### 8.2 财经自定义词典 (financial_dict.txt)

jieba 分词器加载的自定义词典，确保财经术语被正确拆分。

**文件位置**：`config/financial_dict.txt`

**格式**：每行一个词，格式为 `词 词频 词性`

```
归母净利润 10 n
扣非净利润 10 n
营业收入 10 n
```

**何时需要添加**：
- 发现 jieba 将某个术语错误拆分时（如"归母净利润"被拆成"归母/净利润"而非整体）
- 新增行业的专业术语出现分词不准确

**验证方法**：
```python
import jieba
jieba.load_userdict("config/financial_dict.txt")
print(list(jieba.cut("归母净利润同比增长15%")))
# 期望: ['归母净利润', '同比', '增长', '15', '%']
```

### 8.3 意图权重调优

在 `src/retrieval.py` 中可调整不同意图的检索权重：

```python
INTENT_WEIGHTS = {
    "financial_data":    {"bm25": 0.6, "vector": 0.4},
    "comparison":        {"bm25": 0.5, "vector": 0.5},
    "business_analysis": {"bm25": 0.4, "vector": 0.6},
    "trend":             {"bm25": 0.3, "vector": 0.7},
    "general":           {"bm25": 0.5, "vector": 0.5},
}
```

**调优原则**：
- BM25 权重高：适合精确关键词查询（财务指标、数据点）
- 向量权重高：适合语义理解查询（趋势分析、业务解读）

## 九、文档质量要求

### 9.1 PDF 格式要求

| 要求 | 说明 |
|------|------|
| 文字型 PDF | 必须是可提取文本的 PDF（非扫描图片型） |
| 文件大小 | 建议 < 50MB，超大文件可能解析超时 |
| 编码 | 内置中文字体支持 |
| 页码 | 建议包含页码信息（用于来源引用） |
| 表格 | 文本型表格可被解析为 Markdown 表格 |

### 9.2 命名规范

推荐的文件命名格式：

```
[来源机构] 公司名 - 报告标题.pdf

示例：
【华泰证券】中芯国际（688981）：上调港股目标价到63港币.pdf
电信2024年度报告.pdf
移动2024年度报告.pdf
```

**命名要点**：
- 必须包含公司名称（用于自动识别）
- 建议包含年份信息
- 避免使用特殊字符导致路径问题

### 9.3 内容建议

| 要素 | 重要性 | 说明 |
|------|--------|------|
| 财务数据 | 高 | 营收、利润、增长率等核心指标 |
| 时间维度 | 高 | 明确的时间范围（年度、季度） |
| 结构化表格 | 中 | 表格格式优于纯文本描述 |
| 公司全称 | 高 | 首次出现时使用完整公司名 |
| 行业术语 | 中 | 使用标准行业术语，避免俚语 |

## 十、常见问题与解决方案

### Q1：新增文档后查询不到新内容

**原因**：索引未重建，旧索引中不包含新文档的向量。

**解决**：
```bash
python src/ingestion.py --company <公司名> --rebuild
```

### Q2：PDF 解析失败

**原因**：可能是 PDF 格式问题或 API 配额不足。

**排查步骤**：
1. 确认 PDF 是文字型而非扫描图片型
2. 检查 `MINERU_API_KEY` 是否正确
3. 检查 MinerU API 配额是否充足
4. 查看解析日志中的错误信息

### Q3：公司名识别错误

**原因**：文件名中没有包含系统可识别的公司关键词。

**解决**：
1. 重命名文件，包含完整的公司名称
2. 或在 `src/pdf_mineru.py` 的 `_extract_company_name()` 中添加新关键词
3. 或在 `subset.csv` 中手动指定公司名

### Q4：FAISS 索引重建时 Embedding API 调用失败

**原因**：批量请求过于频繁或 API 配额不足。

**解决**：
1. 确认 `BATCH_SIZE=10`（text-embedding-v3 的最大批量上限）
2. 代码中已有重试机制（最多 3 次，指数退避）
3. 检查 DashScope 控制台的 API 调用配额

### Q5：索引重建后查询结果评分异常

**原因**：向量归一化问题。

**检查**：`src/retrieval.py` 和 `src/ingestion.py` 中是否对向量做了 L2 归一化处理（`IndexFlatIP` 内积搜索需要归一化向量）。

### Q6：新增行业的术语检索效果差

**原因**：BM25 扩展词典和 jieba 财经词典未覆盖新行业术语。

**解决**：
1. 在 `config/bm25_expansions.json` 中添加新行业术语扩展
2. 在 `config/financial_dict.txt` 中添加 jieba 自定义词
3. 运行 TDD 测试验证检索效果
